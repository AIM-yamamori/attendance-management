# Streamlitアプリのデプロイ方法について（費用最優先）

## 現状の構成（変更なし）

- **Streamlit**（Python製Webアプリ）
- **Docker**でコンテナ化
- **SQLite**（ファイルベースのDB。外部DBサーバー不要）
- **.env**（環境変数ファイルで設定値・秘密情報を管理）
- **LibreOffice**（ドキュメント変換処理）

```dockerfile
RUN apt-get update && apt-get install -y --no-install-recommends \
    libreoffice-calc \
    libreoffice-core \
    fonts-noto-cjk \
    locales \
    && localedef -i ja_JP -c -f UTF-8 -A /usr/share/locale/locale.alias ja_JP.UTF-8 \
    && rm -rf /var/lib/apt/lists/*
```

**SQLiteはファイル1つで完結するDBのため、外部のマネージドDBサービス（Cloud SQL等）が不要**。これにより「コンテナ＋永続ディスク1つ」があれば構成が完結し、選択肢がシンプルになる。ただし、SQLiteはファイルベースのため、**永続ディスクを持てない環境（ディスクが再起動のたびに初期化される環境）ではデータが消える**点に注意が必要。

**最優先事項：費用をなるべく抑えること。Cloudflareの利用は必須条件ではなく、他の方法も含めてフラットに比較する。**

---

## 比較サマリー

| 案 | 月額費用目安 | 運用開始までの工数 | 難易度 | Cloudflare |
|---|---|---|---|---|
| 案A: VPS単体 | 約500〜1,200円 | 半日〜1日 | 中 | 不使用 |
| 案B: VPS + Cloudflare（無料枠） | 約500〜1,200円 | 半日〜1日 | 中 | 使用（無料） |
| 案C: Fly.io | 無料〜数百円 | 2〜4時間 | 低〜中 | 不使用（併用も可） |
| 案D: Railway | 無料枠なし／実質$5〜 | 1〜2時間 | 低 | 不使用（併用も可） |
| 案E: Render | 無料あり（スリープ）／$7〜 | 1〜2時間 | 低 | 不使用（併用も可） |
| 案F: Cloudflare Containers | 数百円〜（従量課金） | 1〜2日 | 高 | 必須 |

**結論を先に言うと、SQLiteを使う今回の構成では「永続ディスクを安定して持てるか」が最重要な選定基準になる。** この観点で以下、各案を詳しく見ていく。

## 案A: VPS単体（Cloudflare不使用）

最安クラスのVPSを1台契約し、Docker・Streamlit・SQLite・LibreOffice・.envをすべてそこに同居させる、最もシンプルな構成。

### できること・担当範囲
VPS1台が**ドメイン以外の全て**（アプリ実行・SQLiteファイルの永続化・.envの管理・LibreOffice実行・SSL証明書・保守）を担う。ドメインはドメイン取得会社（お名前.com等）のネームサーバーで管理する。

### メリット
- 構成がシンプルで管理対象が1つ（VPS会社の契約のみ）
- SQLiteのファイルはVPSのディスクにそのまま置けるため、**永続化の不安が一切ない**
- 月額固定費用のため予算が読みやすい
- サーバーに直接SSHでき、既存のDocker構成をほぼそのまま持ち込める

### デメリット
- CDN・WAF（不正アクセス対策）がない。DDoS等への耐性が低い
- SSL証明書は自分で発行・更新設定が必要（Let's Encrypt、無料だが手間はかかる）
- サーバーの保守（OSアップデート、障害対応）を自社で行う必要がある
- 冗長化していないため、VPSが落ちるとサービス全体が止まる

### 費用目安
- VPS：月額500〜1,200円程度（さくらの VPS 2GBプラン、ConoHa VPS等の最安〜中位プラン）
- ドメイン：年間1,000〜2,000円程度（.comの場合）
- **合計：月換算で約600〜1,300円程度**

### 運用開始までの工数
- VPS契約・初期設定：1〜2時間
- Docker環境構築・デプロイ：2〜3時間
- SSL設定・動作確認：1〜2時間
- **合計：半日〜1日程度**

### 難易度
**中。** Linuxサーバーの基本操作（SSH、Docker、Nginx設定）が必要。過去にサーバー構築経験があれば問題ないが、未経験だと詰まりやすい箇所がある。

### デプロイ手順
1. VPS（さくらのVPS、ConoHa VPS等）を契約し、Ubuntu等でサーバーを立てる
2. `apt update && apt install docker.io docker-compose` でDocker環境を構築
3. 既存のDockerfileと `docker-compose.yml` をサーバーに配置（SQLiteファイルの保存先はホスト側ディレクトリにボリュームマウントし、永続化する）
4. `.env` ファイルをサーバー上に直接配置（Gitには含めず、SCP等で安全に転送）
5. `docker compose up -d` でコンテナを起動
6. ドメインを取得し、VPSのグローバルIPにAレコードを設定
7. Nginxをリバースプロキシとして設定し、80/443番ポートでStreamlit（デフォルト8501番ポート）へ振り分け
8. Certbot（Let's Encrypt）でSSL証明書を取得し、自動更新のcronを設定
9. `ufw` 等でファイアウォールを設定し、不要なポートを閉じる

## 案B: VPS + Cloudflare（無料枠のみ使用）

案Aと基本構成は同じだが、ドメイン・CDN・WAF・SSLの部分だけCloudflareの**無料プラン**を使う構成。Cloudflare Tunnelを使えばVPS側のポートを一切外部公開せずに済む。

### できること・担当範囲
- **VPSの担当:** アプリ実行（Streamlit＋LibreOffice）、SQLiteファイルの永続化、.envの管理
- **Cloudflareの担当（無料）:** ドメイン・DNS、CDN、WAF/DDoS対策、SSL証明書、Tunnel経由の通信経路

### メリット
- 案Aの費用感をほぼ維持したまま、**無料でCDN・WAF・自動SSLが手に入る**
- Cloudflare Tunnelを使うとVPS側で80/443番ポートを外部に開ける必要がなくなり、セキュリティが向上
- SQLiteの永続化はVPS側で完結するため、案Aと同様に不安がない

### デメリット
- Cloudflareの管理画面・Tunnel設定という学習コストが案Aに追加される
- Tunnelの常時起動（`cloudflared`のサービス化）を忘れると接続が切れる

### 費用目安
- VPS＋ドメイン：案Aと同じ（月換算 約600〜1,300円）
- Cloudflare：**無料**
- **合計：案Aとほぼ同額（追加費用ゼロ）**

### 運用開始までの工数
- 案Aの工数＋Cloudflare Tunnel設定（1時間程度）
- **合計：半日〜1日程度**

### 難易度
**中。** 案Aに加えて`cloudflared`のセットアップが必要だが、公式手順に従えば大きな障壁はない。

### デプロイ手順
1. 案Aの手順1〜5（VPS契約〜Dockerコンテナ起動）と同じ
2. Cloudflareに無料アカウントを作成し、ドメインをネームサーバーごとCloudflareに移管（またはCNAME委任）
3. VPSに`cloudflared`をインストールし、`cloudflared tunnel login`でアカウント連携
4. `cloudflared tunnel create <トンネル名>` でトンネルを作成
5. `config.yml`でStreamlitのポート（8501）へのルーティングを設定
6. Cloudflareダッシュボードでトンネルに対応するDNSレコード（CNAME）を追加
7. `cloudflared`をsystemdサービス化し、サーバー再起動時も自動起動するよう設定
8. Cloudflare側でSSL/TLSモードを「Full」に設定し、動作確認

## 案C: Fly.io

Dockerfileをそのままデプロイできるサービス。永続ディスク（Volumes）を持てるため、SQLiteとの相性が良い。

### できること・担当範囲
Fly.ioが**ドメイン以外のほぼすべて**（アプリ実行、SQLite永続化用のVolume、.envに相当するSecrets管理）を担う。独自ドメインを使う場合のみ、ドメイン管理会社かCloudflareのDNS設定が必要。

### メリット
- Dockerfileがそのまま使える。既存構成の変更がほぼ不要
- **Volumes機能で永続ディスクを持てるため、SQLiteファイルの永続化に対応**
- 無料枠があり、小規模な使用なら無料〜数百円で収まる可能性がある
- 東京リージョンに対応しており、日本からのアクセスでも速度面で有利

### デメリット
- 完全従量課金のため、アクセスが増えると費用が読みにくくなる
- 過去に大規模障害の実績があり、安定性はVPSほど盤石ではないという評価もある
- CLI操作が中心で、GUIでの管理に慣れている場合はやや取っつきにくい

### 費用目安
- 小規模な常時稼働（1インスタンス・最小構成）で**月0〜500円程度**
- Volumeの容量に応じて追加費用（数十円〜）
- **合計：月0〜1,000円程度（アクセス次第で変動）**

### 運用開始までの工数
- アカウント作成・CLIインストール：30分
- `fly launch`でのデプロイ：1〜2時間（Dockerfileの調整が必要な場合あり）
- Volume設定・.env移行：30分〜1時間
- **合計：2〜4時間程度**

### 難易度
**低〜中。** CLIコマンドが中心で手順自体はシンプルだが、Volumeのマウント設定や`fly.toml`の理解が多少必要。

### デプロイ手順
1. `flyctl`をインストールし、`fly auth login`でアカウント作成・ログイン
2. プロジェクトディレクトリで`fly launch`を実行（既存Dockerfileを自動検出）
3. `fly volumes create`でSQLiteファイル保存用の永続ボリュームを作成
4. `fly.toml`でボリュームのマウントパス（SQLiteファイルの保存先ディレクトリ）を設定
5. `.env`の内容を`fly secrets set KEY=VALUE`コマンドで登録（.envファイルそのものはリポジトリに含めない）
6. `fly deploy`でデプロイ
7. 独自ドメインを使う場合は`fly certs add <ドメイン>`を実行し、表示されたDNSレコードをドメイン管理会社（またはCloudflare）側で設定

## 案D: Railway

GitHubリポジトリを連携するだけで自動デプロイされる、開発体験重視のPaaS。

### できること・担当範囲
Railwayが**ドメイン以外のほぼすべて**を担う。永続ボリュームにも対応。

### メリット
- GitHub連携のみでビルド・デプロイが完結し、導入が最も簡単な部類
- 環境変数（.envの内容）をダッシュボードのGUIで設定でき、扱いやすい
- Volumeで永続化に対応しており、SQLiteの運用も可能

### デメリット
- **無料枠がなく**、利用開始時点から少額課金が発生する
- 完全従量課金のため、想定より費用がかさむ可能性があり、Spend Cap（上限設定）を必ず設定する必要がある
- 日本リージョンの提供がなく、海外リージョン経由になるためレイテンシがやや不利

### 費用目安
- Hobbyプランで**$5/月のクレジット付与**があり、小規模利用ならこの範囲に収まる可能性が高い
- 超過分は使用量課金（CPU・メモリ・ボリューム・通信量に応じて加算）
- **合計：月$5前後（為替次第で750円前後）〜、要Spend Cap設定**

### 運用開始までの工数
- GitHubリポジトリ連携・自動デプロイ：30分〜1時間
- Volume設定・環境変数登録：30分
- **合計：1〜2時間程度（最も早い）**

### 難易度
**低。** GUI操作が中心で、Dockerやサーバーの知識がなくても進めやすい。

### デプロイ手順
1. GitHubにリポジトリ（Dockerfile含む）をプッシュ
2. Railwayにログインし、「New Project」からGitHubリポジトリを連携
3. Railwayが自動的にDockerfileを検出しビルド・デプロイを開始
4. 「Variables」タブで.envの内容を1件ずつ登録（またはenvファイルを一括インポート）
5. 「Volumes」機能を追加し、SQLiteファイルの保存先ディレクトリをマウント
6. 「Settings」から必ず「Usage Limit（Spend Cap）」を設定し、想定外の課金を防止
7. 独自ドメインを使う場合は「Settings」→「Networking」からドメインを追加し、表示されたCNAMEをドメイン管理会社（またはCloudflare）側で設定

## 案E: Render

Heroku的な体験に近い、固定料金制のPaaS。無料プランもあるが制限が大きい。

### できること・担当範囲
Renderが**ドメイン以外のほぼすべて**を担う。永続ディスクは有料プランのみ対応。

### メリット
- 無料プランがあり、検証用途であれば費用ゼロで試せる
- 有料プランは固定料金制のため、Railwayよりも費用の見通しが立てやすい
- Herokuに近い操作感で、GitやDockerfileからのデプロイもシンプル

### デメリット
- **無料プランは15分操作がないとスリープし、初回アクセスが遅くなる**（常時稼働のアプリ用途には不向き）
- SQLiteの永続化には有料プラン（Persistent Disk対応）が必須
- 日本リージョンがなく、オレゴン・フランクフルト・シンガポール等海外経由になる

### 費用目安
- 無料プラン：$0（ただしスリープ・永続ディスクなしのため今回の要件には不十分）
- 有料プラン（Persistent Disk利用）：**$7/月〜（約1,050円〜）**
- **合計：月約1,050円〜（無料では要件を満たせない点に注意）**

### 運用開始までの工数
- GitHubリポジトリ連携・デプロイ：30分〜1時間
- Persistent Disk設定・環境変数登録：30分
- **合計：1〜2時間程度**

### 難易度
**低。** GUI中心の操作で、Railwayと同程度に扱いやすい。

### デプロイ手順
1. GitHubにリポジトリ（Dockerfile含む）をプッシュ
2. Renderにログインし、「New Web Service」からリポジトリを連携
3. Dockerfileを自動検出させ、有料プラン（Persistent Disk対応インスタンス）を選択
4. 「Environment」タブで.envの内容を登録
5. 「Disks」機能でSQLiteファイル保存用のディスクをマウント
6. デプロイを実行し、発行されたURLで動作確認
7. 独自ドメインを使う場合は「Settings」→「Custom Domain」から追加し、CNAMEをドメイン管理会社（またはCloudflare）側で設定

## 案F: Cloudflare Containers（参考・Cloudflare必須の場合のみ）

Cloudflare上でDockerコンテナを直接動かす、2026年4月GAの比較的新しいサービス。今回は「Cloudflare必須ではない」という前提のため参考扱いとするが、比較のために記載する。

### できること・担当範囲
Cloudflareが**ドメイン・CDN・WAF・アプリ実行のすべて**を担う。ただしSQLiteの永続化には注意点がある。

### メリット
- ドメイン・CDN・WAF・アプリ実行のすべてを1つの契約で完結できる
- Dockerfileをそのまま利用可能

### デメリット
- **最大のネック：コンテナのディスクは基本的にエフェメラル（使い捨て）であり、SQLiteファイルを安定して永続化する標準的な方法がまだ確立されていない。** R2（オブジェクトストレージ）をFUSEでマウントする方法はあるが、SQLiteのようなランダムアクセスの多いファイルDBとの相性は良くなく、パフォーマンス・信頼性の面で他の案より不利
- 従量課金のため、常時稼働のStreamlitアプリでは費用が読みにくい
- 無操作時のスリープ挙動があり、常時稼働を前提とした設計への対応が別途必要
- サービス自体が新しく、情報・実績が少ない

### 費用目安
- 従量課金（Active-CPU課金）：**月数百円〜だが、稼働時間次第で大きく変動**
- **合計：予測が難しい。事前のPoCでの実測が必須**

### 運用開始までの工数
- Workers Paidプラン契約、`wrangler`セットアップ：1〜2時間
- コンテナビルド・Workerコード実装：半日程度
- SQLite永続化の代替設計（R2連携等）の検証：追加で半日〜1日
- **合計：1〜2日程度（他案より長い）**

### 難易度
**高。** TypeScriptでのWorkerコード実装が必要な上、SQLiteの永続化について標準的でない対応が求められるため、他の案より技術的ハードルが高い。

### デプロイ手順（参考）
1. Cloudflareの有料プラン（Workers Paid）を契約
2. `wrangler` CLIをセットアップし、既存Dockerfileから`wrangler containers build`でイメージをビルド
3. `wrangler.toml`でインスタンスタイプ、`sleepAfter`（スリープまでの時間）を設定
4. コンテナを呼び出すWorkerコードを実装
5. SQLiteファイルの永続化方法を個別に検証・設計（R2連携等、標準的な解決策がないため独自対応が必要）
6. `.env`相当の設定は`wrangler secret put`で登録
7. `wrangler deploy`でデプロイ
8. カスタムドメインをCloudflareダッシュボードで設定
9. 本番投入前に、LibreOffice変換処理とSQLite書き込みを含めた負荷テストを実施（必須）

**今回はSQLiteを使う構成のため、この案は費用最優先の観点でもリスクの観点でも優先度が低い。**

## 結論・提案

**費用を最優先し、かつSQLiteの永続化を安全・確実に行いたいなら「案B: VPS + Cloudflare（無料枠）」を第一候補として提案したい。** 理由は以下の通り。

1. SQLiteはファイルベースのDBのため、**永続ディスクを確実に持てる環境が必須**。この点でVPS（案A・B）は最も不安がなく、Fly.io/Railway（案C・D）もVolumes機能で対応可能。一方Cloudflare Containers（案F）は標準的な永続化手段がなく、今回の構成には現時点でリスクが高い。
2. 費用面では案A・Bが最安クラスで、Cloudflareの無料プランを使えば追加費用なしにCDN・WAF・自動SSLが手に入る（案B）。
3. **すぐに立ち上げたい・運用工数を最小にしたいなら「案C: Fly.io」または「案D: Railway」も有力な代替案。** 特にFly.ioは無料枠があり、東京リージョン対応で日本からのアクセスも速い。
4. **案E: Renderは無料プランではSQLiteの永続化ができない**ため、今回の要件では有料プラン前提となり、優先度はやや下がる。
5. **案F: Cloudflare Containersは「Cloudflareのみで完結させたい」という強いこだわりがない限り、今回は見送りが妥当。** SQLiteとの相性、費用の読みにくさ、技術的難易度の高さがネックになる。

小規模かつサーバー運用に慣れているなら案B、運用工数を極力減らしたいなら案C（Fly.io）が現実的なバランス案となる。
