## 1. 概要

### 1.1 目的

現在Excelファイル（勤務実績管理表）を個人ごと・月ごとに作成し、OneDrive上で管理している勤怠管理業務を、Webシステム化する。ユーザーはブラウザから勤怠を入力・閲覧でき、管理者（admin）は全ユーザーの勤怠を閲覧・編集・PDF出力・編集ロック管理できるようにする。

### 1.2 対象システムの範囲

- フロントエンド：ブラウザで動作するWebアプリケーション
- バックエンド：勤怠データの保存・検証・PDF出力・ロック制御を担うロジック
- データストア：OneDrive上のExcelファイル群（ユーザー×月ごとのファイル）を実データベースとして利用

### 1.3 技術構成

**Streamlit（Python）による一体型Webアプリケーションとして構築する。**

フロントエンド・バックエンドをStreamlit上で一体的に実装し、単一のPythonアプリケーション内で入力画面・閲覧画面・admin機能・OneDrive連携・PDF出力・バリデーション・ロック管理のすべてを完結させる。

## 2. 用語定義

| 用語 | 説明 |
|---|---|
| 勤務実績管理表 | 1ユーザー・1ヶ月分の勤怠を記録するExcelファイル（アップロードされたサンプルが原本） |
| テンプレート | 新規月次ファイルを生成する際の元となるExcelファイル（`原本`シートを使用） |
| ロック | 対象月の勤怠Excelファイルを編集不可にする状態。全体ロック・個別ロックがある |
| adminユーザー | 全ユーザーの勤怠を閲覧・編集・PDF出力・ロック管理できる管理者権限ユーザー |
| 一般ユーザー | 自分自身の勤怠のみ入力・閲覧できるユーザー |

## 3. 利用者・権限要件

### 3.1 ユーザー種別

| 種別 | 認証 | 主な操作 |
|---|---|---|
| admin | 独自ID・パスワード | 全ユーザーの勤怠閲覧、全ユーザーの勤怠Excelの編集、Excel→PDF変換・出力、月次勤怠Excelの編集ロック（一括／個別）、ロック解除（個別） |
| 一般ユーザー | 独自ID・パスワード（ユーザーごとに個別アカウント） | 自分の勤怠の入力、自分の勤怠の閲覧 |

> adminユーザーは自分自身の勤怠データを持たない。admin専用アカウントは管理業務のみを行い、勤怠入力の対象外とする。

### 3.2 権限マトリクス

| 機能 | 一般ユーザー | admin |
|---|---|---|
| 自分の勤怠入力 | ○（ロックされていない月のみ） | - |
| 自分の勤怠閲覧 | ○ | - |
| 他ユーザーの勤怠閲覧 | × | ○（全ユーザー） |
| 他ユーザーの勤怠Excelの編集 | × | ○（全ユーザー、ロック状態に関わらず編集可能） |
| Excel→PDF出力 | × | ○ |
| 月次一括ロック | × | ○ |
| ユーザー個別ロック | × | ○ |
| ユーザー個別ロック解除 | × | ○ |

> adminは、一般ユーザーに課されるロック制限を受けない。ロック中のファイルであっても、admin権限では編集操作が可能とする。

## 4. 機能要件

### 4.1 認証・ログイン

- ユーザーはログインし、自分がadminか一般ユーザーかに応じた画面を表示する。
- ログイン方式は**独自のID・パスワード認証**とする（Microsoft 365等の外部認証には依存しない）。
- 一般ユーザーは氏名（またはユーザーID）ごとに個別アカウントを持つ。

### 4.2 月次Excelファイルの新規作成（テンプレートからの生成）

- 対象月・対象ユーザーを指定すると、テンプレート（原本シート）をコピーし、以下を自動設定してユーザー用の月次ファイルを生成する。

| セル | 内容 | 設定方法 |
|---|---|---|
| C8 | 対象月の初日（例：2026/06/01） | 対象月指定に応じてシステムが自動設定 |
| O5 | 社員番号 | ユーザーマスタから自動設定 |
| AH5 | 氏名 | ユーザーマスタから自動設定 |

- 生成されたファイルは、OneDrive上の該当月フォルダに、ユーザーごとのファイル名で保存する（命名規則は5.1節参照）。
- 派遣先企業名は固定値（自社の企業名）として、全ユーザー・全月で同一の値を自動設定する。
- 派遣先部署名は現時点で運用が未確定（詳細は別紙「確認事項・質問一覧.md」参照）。

### 4.3 勤怠入力（一般ユーザー）

フロント画面から、以下の項目を日ごとに入力できる。バックエンドは入力内容を対応するExcelファイルの該当セルへ反映する。

| 入力項目 | Excel上の位置 | 内容 |
|---|---|---|
| 休暇種類 | D14:D44（各日1行） | プルダウン選択：有休／午前半休／午後半休／長期連休／特別休暇／欠勤／振替休暇／休日出勤／振替出勤／稼働日／休日 |
| 始業時間 | N列 | 時刻入力 |
| 終業時間 | Q列 | 時刻入力 |
| 離業時間（私用外出・自社業務） | AC列 | 時間入力 |
| 自社工数内容 | AP列 | フリーテキスト |

**D列（休暇種類）の入力について**

- D列は以下のいずれかを選択できる：有休／午前半休／午後半休／長期連休／特別休暇／欠勤／振替休暇／休日出勤／振替出勤／稼働日／休日
- 普段の勤怠入力において、D列で「稼働日」を明示的に選択しなくても、始業時間・終業時間を入力することができる（D列が未選択のままでも、平日であれば時刻入力が可能）。

**始業時間・終業時間・離業時間の入力形式**

- 半角数字で入力する。
- `9:30` のような `時:分` の形式でのみ入力を受け付ける。
- 時の先頭に `0` を付けない（例：`09:30` ではなく `9:30`）。
- 上記形式に合致しない入力はエラーとする。

- 入力対象期間はC8で指定された月の日数分（存在しない日付、例：2月30日等は非表示・入力不可）。
- 各行は「日」「曜日」に対応しており、曜日は自動算出（土日は法定休日として自動判定される想定、AY10/AY11の設定に基づく）。
- 実働時間・超過勤務・休日出勤時間・深夜時間等は、既存Excelの計算式に準拠し、システム側（またはExcel側）で自動集計する。
- 上記5項目以外にも、既存Excelには休憩時間等の入力欄が存在するが、これらをフロント入力対象に含めるかは未確定（詳細は別紙「確認事項・質問一覧.md」参照）。

### 4.4 勤怠閲覧

- 一般ユーザー：自分の月次勤怠を選択した月ごとに閲覧できる。
- adminユーザー：全ユーザー・全月の勤怠を閲覧できる（ユーザー・月を指定して検索／一覧表示）。

### 4.5 admin機能：全ユーザーの勤怠Excel編集

- adminは、任意のユーザー・任意の月のExcelファイルを選択し、勤怠入力画面と同様のUIで内容を直接編集できる。
- この編集操作は、当該月がロック状態であっても実行可能とする（ロックは一般ユーザーの入力操作のみを制限する）。
- 編集内容は保存操作によりOneDrive上のExcelファイルへ反映される。
- 編集時のバリデーション（4.6節）は、admin編集時にも同様に適用し、問題のある入力はエラー表示する。

### 4.6 バリデーション（入力エラー表示）

既存Excelの条件付き書式から読み取れた、以下の入力制限をフロントエンド入力時にも同様にエラーとして表示する。

| # | 条件 | 内容 |
|---|---|---|
| 1 | B列（日付）が空欄　かつ　D列（休暇種類）に何か入力しようとしている | エラー：日付が存在しない行には休暇種類を入力できない |
| 2 | B列（日付）が空欄　かつ　N列（始業時間）またはQ列（終業時間）に何か入力しようとしている | エラー：日付が存在しない行には始業時間・終業時間を入力できない |
| 3 | D列（休暇種類）が「有給」「長期連休」「特別休暇」「欠勤」「振替休暇」のいずれか　かつ　N列（始業時間）またはQ列（終業時間）に何か入力されている | エラー：勤務が発生しない休暇区分の日に始業・終業時間が入力されている |
| 4 | 曜日が「土」または「日」　かつ　N列（始業時間）またはQ列（終業時間）に何か入力されている　（下記5の例外を除く） | エラー：休日に始業・終業時間が入力されている |
| 5（例外） | 曜日が「土」または「日」　かつ　D列（休暇種類）に何らかの区分が入力されている場合 | エラーとしない：休日出勤・振替出勤等、休日でも勤務が発生する区分が選択されていれば、N列（始業時間）・Q列（終業時間）への時刻入力を許可する |

- フロントエンドは、上記に該当する入力をリアルタイム、または保存時にエラーメッセージとして表示する。
- バックエンドでも同様のバリデーションを行い、Excel保存前に不正データを検出する（フロント・バック二重チェック）。
- 始業時間・終業時間・離業時間については、上記の入力可否チェックに加えて、4.3節で定めた入力形式（`9:30`形式、半角数字、先頭ゼロなし）に合致するかどうかのフォーマットチェックも行う。

### 4.7 admin機能：Excel → PDF出力

- adminは、データベース（OneDrive）上の指定ユーザー・指定月のExcelファイルを選択し、PDFとして出力できる。
- 出力範囲：`原本`シートの `J1:AQ50` の範囲をPDF化する。用紙サイズはA4縦とする。
- 複数ユーザー分をまとめて出力できるようにする想定（例：対象月の全ユーザー、または選択した複数ユーザーを一括でPDF化）。詳細仕様（1ファイルにまとめるか、ユーザーごとにファイルを分けて一括ダウンロードするか等）は未確定（詳細は別紙「確認事項・質問一覧.md」参照）。

### 4.8 admin機能：編集ロック管理

- 指定した月の勤怠Excelファイルに対し、以下の操作ができる。

| 操作 | 内容 |
|---|---|
| まとめてロック | 指定月の全ユーザーファイルを一括で編集不可にする |
| 個別にロック | 指定月・指定ユーザーのファイルのみ編集不可にする |
| 個別に解除 | ロック済みの指定月・指定ユーザーのファイルを編集可能に戻す |

- ロック状態は、一般ユーザーの入力画面に反映され、ロック中は入力操作を無効化（またはエラー表示）する。
- ロック状態は、Excelファイル自体の保護機能（シート保護等）は使用せず、別途ロック状態管理用のデータストアで「月×ユーザー」単位のロック状態を保持する。実装方式（DB／JSONファイル等）は実装のしやすさを優先して選定してよい。
- 前述のとおり、adminはロック状態に関わらず対象ファイルを編集できる。

## 5. データ要件

### 5.1 データストア構成

- OneDrive上のフォルダ構成：月ごとのフォルダ（`YYYYMM`形式）の下に、ユーザーごとのExcelファイルを格納する。
- ファイル命名規則：`【会社名】勤務実績管理表_YYYYMM_氏名.xlsx`（会社名は固定値）

```
OneDrive指定のディレクトリ/
  ├─ 202606/
  │   ├─ 【会社名】勤務実績管理表_202606_ユーザー1の氏名.xlsx
  │   ├─ 【会社名】勤務実績管理表_202606_ユーザー2の氏名.xlsx
  │   └─ ...
  ├─ 202607/
  │   ├─ 【会社名】勤務実績管理表_202607_ユーザー1の氏名.xlsx
  │   ├─ 【会社名】勤務実績管理表_202607_ユーザー2の氏名.xlsx
  │   └─ ...
```

- PDF出力ファイルも同様に月フォルダ配下に保存する想定。ファイル名はExcelと対になる形とする：`【会社名】勤務実績管理表_YYYYMM_氏名.pdf`（保存要否は別紙「確認事項・質問一覧.md」参照）

### 5.2 OneDriveアクセス

- 保存先は社内のOneDriveを使用する。
- **OneDriveはログイン（サインイン）なしで編集・閲覧できる前提とする。** バックエンドはユーザーの個別サインインを介さず、システム側の設定（共有リンク、アプリ専用アクセス等）により直接ファイルの読み書きを行う。
- そのため、一般ユーザー・adminともに、システムへのログイン（4.1節の独自ID・パスワード認証）のみでよく、**OneDriveへの個別サインインは発生しない。**

### 5.3 閲覧権限とプレビュー

- 保存された勤怠Excelデータは、OneDrive上では全員が閲覧・編集可能な状態にある（ログイン不要でアクセスできる前提のため）。
- 一方、本システムの権限要件（3.2節）では「一般ユーザーは自分の勤怠のみ閲覧可」としているため、**OneDriveファイル自体へのアクセス制御とは別に、システム（アプリケーション）側でアクセス制御を行う**必要がある。
  - システムの画面経由でアクセスする限りは、一般ユーザーは自分のデータのみが表示され、他ユーザーのデータはアプリケーションレベルで遮断される。
  - OneDrive上のファイルへ直接アクセスされた場合の制御は、システムの権限管理の対象外とする。
- 勤怠データのプレビュー方法（画面上での表示）は、Excelファイルをブラウザ上で直接開くのではなく、バックエンドがExcelの内容を読み取り、Web上の表形式UI（テーブル）として整形して表示する方式とする。Excelそのものをブラウザ内蔵ビューア等で開く方式は取らない。

### 5.4 ユーザーマスタ

- 社員番号・氏名・アカウント情報（ログインID・パスワード等）・権限区分（admin／一般）を管理するマスタが別途必要。

|---|---|

## 7. 画面要件

### 7.1 画面一覧

| 画面 | 対象ユーザー | 内容 |
|---|---|---|
| ログイン画面 | 全員 | ID・パスワードによる認証 |
| 勤怠入力画面 | 一般ユーザー | 月選択→日別の休暇種類・始業/終業時間・離業時間・自社工数内容を入力。バリデーションエラーを表示 |
| 勤怠閲覧画面（自分用） | 一般ユーザー | 月選択→自分の入力内容を一覧表示（プレビュー） |
| 勤怠閲覧・編集画面（全ユーザー） | admin | ユーザー・月を指定して閲覧し、そのまま編集も可能 |

| ロック管理画面 | admin | 月を指定して、まとめてロック／ユーザーごとの個別ロック・解除を操作 |

### 7.2 画面遷移

```
[ログイン]
    │
    ├─ 一般ユーザー ─▶ [勤怠入力／閲覧画面]（自分の月次データのみ）
    │
    └─ admin ────────▶ [管理トップ]
                            ├─▶ [勤怠閲覧・編集画面（全ユーザー）]
                            ├─▶ [PDF出力画面]
                            └─▶ [ロック管理画面]
```

### 7.3 勤怠入力画面（一般ユーザー）詳細

**構成要素**

| 要素 | 内容 |
|---|---|
| ヘッダー | 対象年月の表示・切り替え（前月／翌月、または月選択プルダウン）、氏名・社員番号の表示、ロック状態の表示 |
| 入力テーブル | 1日1行。列：日付／曜日／休暇種類（プルダウン）／始業時間／終業時間／離業時間／自社工数内容 |
| バリデーション表示 | 入力内容に問題がある行はセル・行を強調表示し、エラーメッセージを表示 |
| 保存ボタン | 入力内容をまとめて保存（バックエンド経由でExcelへ反映） |
| ロック中の表示 | ロックされている月は入力欄をすべて無効化し、「この月はロックされています」等のメッセージを表示 |

**休暇種類による入力欄の制御**

- D列（休暇種類）は必須選択ではない。平日であれば、D列を選択しなくても始業時間・終業時間の入力欄は有効。
- D列で「有休」「長期連休」「特別休暇」「欠勤」「振替休暇」を選択した場合、始業時間・終業時間の入力欄を自動的に無効化（グレーアウト）する。
- 曜日が「土」「日」の行は、原則として始業時間・終業時間の入力欄を無効化する。ただし、D列に休暇種類（例：休日出勤、振替出勤等）が選択されている場合は例外的に入力欄を有効化する。
- 「午前半休」「午後半休」の場合は、半日分の勤務時間のみ入力可能とする。

**始業時間・終業時間・離業時間の入力形式**

- 半角数字・`9:30`形式（先頭ゼロなし）でのみ入力を受け付け、それ以外の形式はエラーとする。

**バリデーションエラーの表示例**

- 日付が空欄の行にD列・始業時間・終業時間のいずれかを入力しようとした → 該当セルを警告色で表示し、「この行には入力できません」等のメッセージを表示
- 休暇区分（有休／長期連休／特別休暇／欠勤／振替休暇）を選択した日に始業時間・終業時間が入力されている → 該当行を警告色で表示
- 休日（土・日）で休暇種類が未選択のまま始業時間・終業時間が入力されている → 該当行を警告色で表示し、「休日に稼働時間が入力されています」等のメッセージを表示
- 始業時間・終業時間・離業時間が `9:30` 形式に合致しない（全角数字、先頭ゼロあり等） → 該当セルを警告色で表示し、入力形式の誤りを通知

### 7.4 勤怠閲覧画面（プレビュー・一般ユーザー用）

- 保存済みのExcelファイルの内容を、バックエンドが読み取り、Web上のテーブル形式で整形して表示する。
- 一般ユーザーは自分の月次データのみ選択・閲覧可能。
- 入力欄はすべて読み取り専用（編集不可）とする。

### 7.5 勤怠閲覧・編集画面（admin用）

- adminはユーザー選択欄・月選択欄から任意の組み合わせを選び、勤怠データを閲覧できる。
- 閲覧画面上でそのまま編集操作も行える（7.3節の入力画面と同様のUI・バリデーションを適用）。
- ロック状態に関わらず編集可能。
- 保存操作により、OneDrive上のExcelファイルへ反映される。

### 7.6 PDF出力画面（admin）

- ユーザーを1名または複数名選択し、対象月を指定してPDFを生成する。
- 出力範囲：`J1:AQ50`、A4縦。
- 生成後、ブラウザ上でダウンロードする。

### 7.7 ロック管理画面（admin）

- 対象月を選択すると、その月の全ユーザーのロック状態一覧（ユーザー名・ロック中／編集可能）が表示される。
- 「まとめてロック」ボタンで一括ロック。
- 各ユーザー行に「ロック」「解除」の個別操作ボタンを配置。

## 9. 処理フロー（勤怠入力の例）

1. 一般ユーザーがID・パスワードでログインする。
2. 対象月を選択する。
3. Streamlitアプリが該当ユーザー・該当月のExcelファイルをOneDriveから取得する（存在しなければテンプレートから新規作成）。
4. ロック状態を確認し、ロック中であれば入力不可として表示する。
5. ユーザーが休暇種類・始業時間・終業時間・離業時間・自社工数内容を入力する。
6. バリデーションを実施し、問題があればエラー表示する。
7. 保存操作により、Excelファイルの該当セルを更新し、OneDriveへ書き戻す。

---

## 10. PDF出力フロー（admin）

1. adminがログインする。
2. 対象ユーザー・対象月を選択する。
3. アプリがOneDriveから該当Excelファイルを取得する。
4. Excel→PDF変換処理を行う。
5. PDFをダウンロードする。

---

## 11. ロック管理フロー（admin）

1. adminがログインする。
2. 対象月を選択する。
3. 「まとめてロック」を選択した場合：該当月の全ユーザーファイルをロック状態にする。
4. 「個別にロック」を選択した場合：ユーザーを指定してロック状態にする。
5. 「個別に解除」を選択した場合：ロック済みユーザーを指定して解除する。
6. ロック状態は各ユーザーの入力画面に即時反映される。

---

## 12. admin編集フロー

1. adminがログインする。
2. 対象ユーザー・対象月を選択する。
3. アプリがOneDriveから該当Excelファイルを取得し、編集可能なテーブルとして表示する（ロック状態に関わらず表示・編集可能）。
4. adminが内容を編集する。
5. バリデーションを実施し、問題があればエラー表示する。
6. 保存操作により、Excelファイルの該当セルを更新し、OneDriveへ書き戻す。
