## 1. 概要

### 1.1 目的

現在Excelファイル（勤務実績管理表）を個人ごと・月ごとに作成し、OneDrive上で管理している勤怠管理業務を、Webシステム化する。ユーザーはブラウザから勤怠を入力・閲覧でき、管理者（admin）は全ユーザーの勤怠を閲覧・編集・PDF出力・編集ロック管理できるようにする。

### 1.2 対象システムの範囲

- フロントエンド：ブラウザで動作するWebアプリケーション
- バックエンド：勤怠データの保存・検証・PDF出力・ロック制御を担うロジック
- データストア：OneDrive上のExcelファイル群（ユーザー×月ごとのファイル）を実データベースとして利用

### 1.3 技術構成

**Streamlit（Python）による一体型Webアプリケーションとして構築する。**

フロントエンド・バックエンドをStreamlit上で一体的に実装し、単一のPythonアプリケーション内で入力画面・閲覧画面・admin機能・OneDrive連携・PDF出力・バリデーション・ロック管理のすべてを完結させる。

### 1.4 想定利用規模・設置環境

- 本番環境の設置場所：**クラウド**
- 想定同時利用者数：**10名以下**
- 稼働時間：社内の営業時間内利用を基本とするが、クラウド利用費用の見積り次第で常時稼働か時間限定稼働かを検討する（詳細は別紙「確認事項・質問一覧.md」参照）。

### 1.5 開発環境

- **開発段階では、本番のクラウド環境ではなく、開発者のローカル環境で構築・動作確認を行う。**
- ローカル環境と本番（クラウド）環境で動作の差異が生じないよう、**Docker（コンテナ）を用いた環境構築を行う。** Streamlitアプリ本体、および必要なPythonライブラリ一式をDockerイメージとしてまとめ、ローカルではこのイメージをそのまま起動して開発・動作確認を行う。
- 本番のクラウド環境へデプロイする際も、同じDockerイメージ（またはそれをベースにしたイメージ）を利用することを想定し、ローカルで確認した環境と本番環境の差異を最小限にする。
- 開発時に必要となる主な構成要素は以下のとおり。

| 要素 | 内容 |
|---|---|
| Docker / Docker Compose | アプリケーション本体（Streamlit）の実行環境をコンテナ化する。ローカルでの起動・停止・再構築を統一的なコマンドで行えるようにする |
| Python実行環境（コンテナ内） | Streamlitおよび4章・5章で挙げた機能（Excel読み書き、PDF生成、ハッシュ化パスワード認証等）に必要なライブラリを含む |
| ローカルでのOneDriveアクセス | 開発段階でも、5.2節の共有URL経由でのアクセス方式をそのまま使用する。ローカル環境からインターネット経由でOneDriveの共有URLにアクセスできる回線環境が必要 |
| 環境変数・設定ファイル | OneDrive共有URL等の接続設定値を、ローカル用・本番用で切り替えられるようにする（例：`.env`ファイル等での管理） |

- Docker化の目的は、「開発者のPC環境に依存せず誰でも同じ手順で環境を再現できるようにすること」「ローカルと本番の動作差異を減らすこと」の2点である。具体的なDockerfile・Docker Composeの構成は実装時に検討する。

## 2. 用語定義

| 用語 | 説明 |
|---|---|
| 勤務実績管理表 | 1ユーザー・1ヶ月分の勤怠を記録するExcelファイル（アップロードされたサンプルが原本） |
| テンプレート | 新規月次ファイルを生成する際の元となるExcelファイル。OneDriveのルートディレクトリ直下に配置する（詳細は5.1節参照）。入力・読み出しの対象は`原本`シート。ファイルコピー時は`原本`シートと`記入例`シートのみをコピーし、`変更履歴`シートはコピー不要 |
| ロック | 対象月の勤怠Excelファイルを編集不可にする状態。全体ロック・個別ロックがある |
| adminユーザー | 全ユーザーの勤怠を閲覧・編集・PDF出力・ロック管理できる管理者権限ユーザー |
| 一般ユーザー | 自分自身の勤怠のみ入力・閲覧できるユーザー |

## 3. 利用者・権限要件

### 3.1 ユーザー種別

| 種別 | 認証 | 主な操作 |
|---|---|---|
| admin | 独自ID・パスワード（adminは専用のログインID） | 全ユーザーの勤怠閲覧、全ユーザーの勤怠Excelの編集、Excel→PDF変換・出力、月次勤怠Excelの編集ロック（一括／個別）、ロック解除（個別）、ユーザーマスタの管理（一般ユーザーの追加・編集・削除） |
| 一般ユーザー | 独自ID・パスワード（**ログインIDは社員番号**、ユーザーごとに個別アカウント） | 自分の勤怠の入力、自分の勤怠の閲覧 |

> adminユーザーは自分自身の勤怠データを持たない。admin専用アカウントは管理業務のみを行い、勤怠入力の対象外とする。
> adminアカウントは**1名**とする。ユーザーマスタ（姓・名・社員番号・部署名・パスワード・権限区分）の管理はadminが行う。

### 3.2 権限マトリクス

| 機能 | 一般ユーザー | admin |
|---|---|---|
| 自分の勤怠入力 | ○（ロックされていない月のみ） | - |
| 自分の勤怠閲覧 | ○（ロック状態に関わらず閲覧可能） | - |
| 他ユーザーの勤怠閲覧 | × | ○（全ユーザー） |
| 他ユーザーの勤怠Excelの編集 | × | ○（全ユーザー、ロック状態に関わらず編集可能） |
| Excel→PDF出力 | × | ○ |
| 月次一括ロック | × | ○ |
| ユーザー個別ロック | × | ○ |
| ユーザー個別ロック解除 | × | ○ |

> adminは、一般ユーザーに課されるロック制限を受けない。ロック中のファイルであっても、admin権限では編集操作が可能とする。
> 一般ユーザーは、ロック中の月であっても、自分の勤怠データの**閲覧（読み出し）は常に可能**とする。ロックによって制限されるのは入力（編集）操作のみである。

## 4. 機能要件

### 4.1 認証・ログイン

- ユーザーはログインし、自分がadminか一般ユーザーかに応じた画面を表示する。
- ログイン方式は**独自のID・パスワード認証**とする（Microsoft 365等の外部認証には依存しない）。
- **ログインIDには社員番号をそのまま使用する。** 社員番号は半角数字（3桁・4桁等、桁数はユーザーによって異なる、0埋めなし）で一意な値であるため、別途IDを発番せずログインIDとして流用する。
- パスワードはハッシュ化してユーザーマスタに保存し、平文では保持しない。
- 一般ユーザーは社員番号（ログインID）ごとに個別アカウントを持つ。

### 4.2 月次Excelファイルの新規作成（テンプレートからの生成）

- テンプレートファイルは、OneDriveの**ルートディレクトリ直下**に1つだけ配置する（月フォルダの外側）。
- テンプレートファイル名：`【会社名】勤務実績管理表_テンプレート.xlsx`
- 対象月・対象ユーザーを指定すると、テンプレートファイルのうち**`原本`シートと`記入例`シートをコピー**して、ユーザー用の月次ファイルを生成する。**`変更履歴`シートはコピー不要**とする（月次ファイルには含めない）。
- システムが入力・読み出しの対象とするのは**`原本`シートのみ**とする（`記入例`シートはコピーはするが、システムからは編集しない。ヘルプ機能として参照のみ行う）。

**テンプレートファイルの管理・編集方針**

- テンプレートファイル自体（OneDriveルートディレクトリ直下の`【会社名】勤務実績管理表_テンプレート.xlsx`）は、**本システム（フロントエンドUI）からは編集しない。**
- テンプレートの内容（書式、数式、初期値等）を変更する必要がある場合、**adminがOneDrive上のテンプレートファイルを直接開いて、Excel上で編集する。** 本システムはテンプレートの内容編集機能を持たず、あくまで「テンプレートを読み込んでコピーし、月次ファイルを生成する」役割のみを担う。
- そのため、テンプレートの更新はシステムの外側（Excelアプリケーション上での直接操作）で行われる運用となる。
- **`記入例`シートについては、ユーザーが確認したいときにいつでも参照できるようにする。** 具体的には、勤怠入力・閲覧画面に「ヘルプ」ボタンを設け、押下すると当該ユーザーの月次ファイル内の`記入例`シートの内容を、読み取り専用のプレビューとしてポップアップ等で表示する（14節「既存運用からの移行方針」とあわせて、入力ルールの参照手段として位置づける）。
- 生成時、`原本`シートの以下のセルを自動設定する。

| セル | 内容 | 設定方法 |
|---|---|---|
| C8 | 対象月の初日（`YYYY/MM/01`形式、例：2026/06/01） | 対象月指定に応じてシステムが自動設定 |
| O5 | 社員番号 | ユーザーマスタから自動設定 |
| AH4 | 部署名 | ユーザーマスタの部署名から自動設定（ユーザーごとに異なる） |
| AH5 | 氏名（姓と名の間に全角スペースを挿入） | ユーザーマスタの姓・名から自動生成して設定（例：`山田　太郎`） |

**氏名の管理・表記ルール**

- ユーザーマスタでは、氏名を**姓と名を別項目として管理**する（例：姓＝「山田」、名＝「太郎」）。
- 用途に応じて姓・名を異なる形式に結合して使用する。

| 用途 | 結合形式 | 例 |
|---|---|---|
| Excel／PDFのファイル名 | 姓と名の間にスペースを入れない | `山田太郎` |
| Excel内の氏名欄（`AH5`セル） | 姓と名の間に**全角スペース**を挿入 | `山田　太郎` |

**C8セル・フォルダ名・ファイル名の対応**

- C8セルには対象月の初日を `YYYY/MM/01` 形式で設定する（例：`2026/06/01`）。
- このC8セルの年月（`YYYY`＋`MM`）が、OneDrive上のフォルダ名（`YYYYMM`形式、例：`202606`）およびファイル名に含まれる年月部分（例：`202606`）と一致する。
  - 例：C8が `2026/06/01` の場合 → フォルダ名は `202606`、ファイル名は `【会社名】勤務実績管理表_202606_山田太郎.xlsx`

- 生成されたファイルは、OneDrive上の該当月フォルダに、ユーザーごとのファイル名で保存する（命名規則は5.1節参照）。
- 派遣先企業名は固定値として、全ユーザー・全月で同一の値を自動設定する（サンプルファイルに記載の企業名表記に準拠）。
- 派遣先部署名は**ユーザーごとに固定値**を持たせる。ユーザーマスタに部署名を保持し、テンプレート生成時に自動設定する。

**ファイル生成のトリガー（月フォルダの作成を含む）**

- 月次ファイルの新規作成は、事前の一括生成やバッチ処理ではなく、**ユーザー本人が対象月の勤怠入力画面にアクセスしようとしたタイミング**で行う。
  - 対象月のフォルダ（例：`202606`）がOneDriveのルートディレクトリ配下にまだ存在しない場合、**そのユーザーが最初にその月へアクセスした時点で、システムが月フォルダを新規作成する。**（フォルダはユーザーごとに作るのではなく、月ごとに1つ。同じ月に複数ユーザーがいる場合は、最初にアクセスした人の操作でフォルダが作られ、以降は他ユーザーもそのフォルダを共有して使う）
  - 続けて、対象ユーザー・対象月のExcelファイルがそのフォルダ内にまだ存在しない場合、システムがテンプレートからファイルを新規生成し、月フォルダへ保存したうえで入力画面を表示する。
  - 既にファイル（およびフォルダ）が存在する場合は、それをそのまま読み込んで使用する（再生成は行わない）。
- **フォルダ作成の競合対策**：複数ユーザーがほぼ同時に同一の未作成月へ初回アクセスした場合、2人以上が同時にフォルダ作成を試みる可能性がある。この場合の対策として、フォルダ作成処理は「フォルダが存在しなければ作成し、既に存在すればそれを使う（存在チェック→作成の非同期な重複を許容する実装、いわゆる冪等な作成処理）」とし、複数リクエストが同時にフォルダ作成を試みても、結果的に同じ名前のフォルダが1つだけ存在する状態に収束するようにする。フォルダ作成の重複によるエラーが発生した場合は、エラーとして扱わず「既に作成済みのフォルダを使う」扱いとして処理を継続する。
  - 同様の考え方を、ユーザーごとのExcelファイル生成（4.2節前半）にも適用する。同一ユーザー・同一月のファイルに対して、ブラウザの多重クリックや複数タブ操作等により生成リクエストが重複した場合も、最終的に1つのファイルに収束させ、上書きによるデータ消失が起きないようにする（詳細な排他制御方針は13章参照）。

### 4.3 勤怠入力（一般ユーザー）

フロント画面から、以下の項目を日ごとに入力できる。バックエンドは入力内容を対応するExcel（`原本`シート）の該当セルへ反映する。

**バックエンドがExcelへ値を書き込む際は、対象セルの値のみを更新し、元のExcelファイルが持つ書式（フォント、罫線、セルの背景色、条件付き書式、列幅・行高、数式等）を崩さないこと。** セル単位での値の上書きにとどめ、シート全体の書式を再生成・再構築するような処理は行わない。

**フロントエンドUIのテーブルは、Excel（`原本`シート）の列配置とは異なるレイアウトとする。** Excel側はD列・N列・Q列・AC列・AP列など離れた列に項目が点在しているが、フロントのテーブルはユーザーが見やすいよう、日付・曜日に続けて入力項目を隙間なく並べた独自の列順で構成する（詳細な画面構成は7.4節参照）。そのため、以下の対応表は「フロントの項目」と「Excel上の格納先セル」の対応関係を示すものであり、フロントの画面上の列順そのものではない。

| 入力項目（フロントUI） | Excel（`原本`シート）上の格納位置 | 内容 |
|---|---|---|
| 休暇種類 | `D14:D44`列（各日1行） | プルダウン選択：有休／午前半休／午後半休／長期連休／特別休暇／欠勤／振替休暇／休日出勤／振替出勤／稼働日／休日 |
| 始業時間 | `N`列 | 時刻入力 |
| 終業時間 | `Q`列 | 時刻入力 |
| 離業時間（私用外出・自社業務） | `AC`列 | 時間入力（入力形式・UIの要件は始業時間・終業時間と同様） |
| 自社工数内容 | `AP`列 | フリーテキスト |

**D列（休暇種類、Excel上の呼称）の入力について**

- 以降、本書でバリデーションルールを記述する際、「D列」「N列」「Q列」等はすべて**Excel（`原本`シート）上のセル位置**を指す。フロントエンドUIのテーブル上の列位置を指す場合は、その都度「フロントUIの休暇種類欄」のように明記する（7.4節参照）。
- D列（Excel上）は以下のいずれかを選択できる：有休／午前半休／午後半休／長期連休／特別休暇／欠勤／振替休暇／休日出勤／振替出勤／稼働日／休日
- 普段の勤怠入力において、D列（Excel上）で「稼働日」を明示的に選択しなくても、始業時間・終業時間を入力することができる（D列が未選択のままでも、平日であれば時刻入力が可能）。

**始業時間・終業時間・離業時間の入力形式**

- Excel（`原本`シート）上のデータ形式：半角数字・`9:30` のような `時:分` 形式とし、時の先頭に `0` を付けない（例：`09:30` ではなく `9:30`）。
- **フロントエンドでは、`9:30`のようなコロン区切りのテキスト表記そのものを入力形式として使用しない。** 「時」と「分」を別々の入力要素（例：時のプルダウン＋分のプルダウン、または時刻選択UI）として受け付け、ユーザーが`:`（コロン）を含む文字列を直接タイプする方式は採用しない。
- 分の指定は**1分単位**で選択・入力できることを必須とする（5分刻み等の丸めは行わない）。
- フロントで受け取った「時」「分」の数値は、そのままExcel側の`9:30`形式（半角数字、先頭ゼロなし）と**一致する値**として扱われるため、バックエンド側で改めて形式変換を行う処理は不要とする。フロントの入力構造自体が、Excelの記述ルールに沿った値のみを生成する設計とする。

- 入力対象期間はExcel（`原本`シート）のC8で指定された月の日数分（存在しない日付、例：2月30日等はフロントUI上でも非表示・入力不可とする）。
- 各行は「日」「曜日」に対応しており、曜日は自動算出（Excel上、土日は法定休日として自動判定される想定、`AY10`/`AY11`の設定に基づく）。
- 実働時間・超過勤務・休日出勤時間・深夜時間等は、既存Excelの計算式に準拠し、システム側（またはExcel側）で自動集計する。
- 休憩時間に関する欄（Excel `F11:G16`、`F18:H21`）はユーザーの入力対象外と確定した（詳細は次項「フロント入力対象外とするセル範囲」参照）。

**フロント入力対象外とするセル範囲**

- Excel（`原本`シート）の `F11:G16` および `F18:H21` は、**ユーザーの入力対象としない。** テンプレートに元々設定されている状態（数式・固定値等）をそのまま維持し、システムからは参照・編集・上書きを一切行わない。
- 上記範囲は、月次ファイルをテンプレートから生成する際にコピーされた状態のまま保持され、フロントエンドUIにも表示しない。

### 4.4 勤怠閲覧

- 一般ユーザー：自分の月次勤怠を選択した月ごとに閲覧できる。
- adminユーザー：全ユーザー・全月の勤怠を閲覧できる（ユーザー・月を指定して検索／一覧表示）。
- 休暇申請等に関する上長承認ワークフローは設けない。ユーザーは自身の勤怠を入力するのみで、承認プロセスは本システムのスコープ外とする。

### 4.5 admin機能：全ユーザーの勤怠Excel編集

- adminは、任意のユーザー・任意の月の**月次Excelファイル**（テンプレートではなく、ユーザーごとに生成された実データファイル）を選択し、勤怠入力画面と同様のUIで内容を直接編集できる。
- テンプレートファイル自体はこの機能の対象外であり、4.2節のとおりadminがOneDrive上で直接編集する運用とする。
- この編集操作は、当該月がロック状態であっても実行可能とする（ロックは一般ユーザーの入力操作のみを制限する）。
- 編集内容は保存操作によりOneDrive上のExcelファイルへ反映される。
- 編集時のバリデーション（4.6節）は、admin編集時にも同様に適用し、問題のある入力はエラー表示する。

### 4.6 バリデーション（入力エラー表示）

既存Excelの条件付き書式から読み取れた、以下の入力制限をフロントエンド入力時にも同様にエラーとして表示する。これらのルールは、業務上の厳密な制約というより、表の見やすさ・入力ミスの早期発見を意図したものである。

**表記ルール**：以下の表における「B列」「D列」「N列」「Q列」は、すべて**Excel（`原本`シート）上のセル位置**を指す。フロントエンドUIのテーブル上では、これらはそれぞれ「日付欄」「休暇種類欄」「始業時間欄」「終業時間欄」として、4.3節・7.4節に示す独自レイアウトの列に対応する（Excel上の列順とフロントUIの列順は一致しない）。

| # | 条件（Excel `原本`シート上の列基準） | フロントUI上の対応欄 | 内容 |
|---|---|---|---|
| 1 | Excel `B`列（日付）が空欄　かつ　Excel `D`列（休暇種類）に何か入力しようとしている | 日付欄が空欄の行の、休暇種類欄への入力 | エラー：日付が存在しない行には休暇種類を入力できない |
| 2 | Excel `B`列（日付）が空欄　かつ　Excel `N`列（始業時間）または`Q`列（終業時間）に何か入力しようとしている | 日付欄が空欄の行の、始業時間欄・終業時間欄への入力 | エラー：日付が存在しない行には始業時間・終業時間を入力できない |
| 3 | Excel `D`列（休暇種類）が「有給」「長期連休」「特別休暇」「欠勤」「振替休暇」のいずれか　かつ　Excel `N`列（始業時間）または`Q`列（終業時間）に何か入力されている（**逆方向も同様にエラー**：既に`N`列または`Q`列に時刻が入力されている状態で、上記いずれかの休暇種類を新たに選択した場合も同じ扱い） | 休暇種類欄が上記区分の行の、始業時間欄・終業時間欄への入力（および、時刻入力済みの行で休暇種類欄を上記区分に変更する操作） | エラー：勤務が発生しない休暇区分の日に始業・終業時間が入力されている。入力の順序（先に休暇種類を選ぶか、先に時刻を入れるか）に関わらず、両者が同時に成立する状態はすべてエラーとする |
| 4 | 曜日が「土」または「日」　かつ　Excel `N`列（始業時間）または`Q`列（終業時間）に何か入力されている　（下記5の例外を除く） | 曜日が土日の行の、始業時間欄・終業時間欄への入力 | エラー：休日に始業・終業時間が入力されている |
| 5（例外） | 曜日が「土」または「日」　かつ　Excel `D`列（休暇種類）に何らかの区分が入力されている場合 | 曜日が土日の行で、休暇種類欄に区分が選択されている場合の、始業時間欄・終業時間欄への入力 | エラーとしない：休日出勤・振替出勤等、休日でも勤務が発生する区分が選択されていれば、始業時間・終業時間への時刻入力を許可する |

- フロントエンドは、上記に該当する入力を**リアルタイムに検知し、エラーメッセージを即時表示する**（保存操作を待たずに、入力・選択の都度チェックする）。ルール3のように「先に時刻を入力し、後から矛盾する休暇種類を選択する」逆順の操作についても、休暇種類欄を変更した瞬間にリアルタイムで検知する。
- **フロントエンドの時刻入力欄（始業時間・終業時間・離業時間）は、`9:30`のようなコロン区切りテキスト表記を入力形式として使用しない。** 時・分を別々の入力要素（プルダウン等）で受け付けることで、形式的に不正な値（全角数字、`9時30分`等の自由記述）がそもそも入力できない構造とする（詳細は4.3節参照）。
- バックエンドでも同様のバリデーションを行い、Excel保存前に不正データを検出する（フロント・バック二重チェック）。
- 時・分を別要素で受け付ける構造上、バックエンドでの形式変換処理は不要となるが、Excelへ書き込む際の最終的な値（時・分の組み合わせ）が`9:30`形式の記述ルールと一致していることを、保存直前にバックエンド側でも確認する。

### 4.7 admin機能：Excel → PDF出力

- adminは、データベース（OneDrive）上の指定ユーザー・指定月のExcelファイルを選択し、PDFとして出力できる。
- 出力範囲：`原本`シートの `J1:AQ50` の範囲をPDF化する。用紙サイズはA4縦とする。
- PDFは**1ユーザー1ファイル**として生成する（複数ユーザー分を1つのPDFに結合することはしない）。
- 複数ユーザーを選択して出力する場合は、生成した複数のPDFファイルを**ZIP形式にまとめてダウンロード**できるようにする。
- **生成したPDFはOneDrive上には保存しない。** ブラウザへの都度ダウンロードのみとし、サーバー側・OneDrive側のいずれにも永続保存しない。
- 想定利用シーンは**月次締め処理時のみ**とし、日常的に頻繁に使う機能ではない前提とする。

### 4.8 admin機能：編集ロック管理

- 指定した月の勤怠Excelファイルに対し、以下の操作ができる。

| 操作 | 内容 |
|---|---|
| まとめてロック | 指定月の全ユーザーファイルを一括で編集不可にする |
| 個別にロック | 指定月・指定ユーザーのファイルのみ編集不可にする |
| 個別に解除 | ロック済みの指定月・指定ユーザーのファイルを編集可能に戻す |

- ロック状態は、一般ユーザーの入力画面に反映され、ロック中は**入力（編集）操作のみ**を無効化する。ロック中であっても、一般ユーザーは自分の勤怠データの閲覧（読み出し）は常に行える。
- ロックは、ユーザーが対象月へ新規にアクセスした時点、および保存操作を行った時点で必ずチェックされる。既に編集画面を開いた状態でadminがロックをかけた場合の詳細な挙動は13.2節を参照。
- ロック状態は、Excelファイル自体の保護機能（シート保護等）は使用せず、別途ロック状態管理用のデータストアで「月×ユーザー」単位のロック状態を保持する。
- **保存場所**：ロック状態管理データは、勤怠Excel群を格納するOneDrive上ではなく、**アプリケーションサーバー側（クラウド環境のストレージ、または5.4節のユーザーマスタと同じデータストア内）**に保存する。OneDriveは共有URLを介して誰でもアクセス可能な前提（5.2節）のため、ロック状態のような管理情報をOneDrive上に置くことは避け、システム専用のデータストアで一元管理する。
- 実装方式（DB／JSONファイル等）に指定はなく、実装のしやすさを優先して選定してよい。ユーザーマスタ（5.4節）と同一のデータストア内にまとめて管理してもよいし、別ファイル・別テーブルとして分離してもよい。
- ロックの解除は**個別解除のみ**とする。「まとめてロック」で一括ロックした月についても、解除操作は必ずユーザーごとに個別に行う（一括解除機能は設けない）。
- 前述のとおり、adminはロック状態に関わらず対象ファイルを編集できる。

**ロック中に一般ユーザーが行える操作の範囲（明確化）**

| 操作 | ロック中の可否 | 補足 |
|---|---|---|
| 対象月のプレビュー（閲覧） | ○ 可能 | 保存済みの内容を読み取り専用で常に閲覧できる |
| 「編集する」への切り替え | × 不可 | 操作自体が無効化され、編集モードに入れない |
| 休暇種類欄・始業時間欄・終業時間欄等の入力・修正（Excel上は`D`・`N`・`Q`・`AC`・`AP`列に対応） | × 不可 | 編集モードに入れないため、そもそも入力操作が発生しない |
| 保存 | × 不可 | 編集不可のため保存操作自体が存在しない |
| ヘルプ（記入例プレビュー）の参照 | ○ 可能 | ロック状態と無関係に常時参照可能 |
| PDF出力 | × 不可（adminのみの機能） | 一般ユーザーはそもそもPDF出力機能を持たない |

> 上記はadminには適用されない。adminはロック状態に関わらず、プレビュー・編集・保存のすべてを常に行える（3.2節・4.5節参照）。

## 5. データ要件

### 5.1 データストア構成

- OneDrive上のフォルダ構成：**OneDriveの「ルートディレクトリ」**の直下にテンプレートファイルを1つ配置し、その配下に月ごとのフォルダ（`YYYYMM`形式）を作成、その中にユーザーごとのExcelファイルを格納する。システムはこのルートディレクトリに対して発行された1つの共有URLを起点として、配下のファイル・フォルダにアクセスする（詳細は5.2節参照）。
- ファイル命名規則：
  - テンプレート：`【会社名】勤務実績管理表_テンプレート.xlsx`
  - 月次データ：`【会社名】勤務実績管理表_YYYYMM_姓名.xlsx`（会社名は固定値、`YYYYMM`はC8セルの年月と一致、氏名は姓と名の間にスペースを入れない）

```
OneDriveルートディレクトリ/（共有URLの起点）
  ├─ 【会社名】勤務実績管理表_テンプレート.xlsx     ← テンプレート本体（直下に配置）
  ├─ 202606/
  │   ├─ 【会社名】勤務実績管理表_202606_山田太郎.xlsx
  │   ├─ 【会社名】勤務実績管理表_202606_佐藤花子.xlsx
  │   └─ ...
  ├─ 202607/
  │   ├─ 【会社名】勤務実績管理表_202607_山田太郎.xlsx
  │   ├─ 【会社名】勤務実績管理表_202607_佐藤花子.xlsx
  │   └─ ...
```

- PDF出力ファイルは、**OneDrive上には保存しない。** ファイル名は生成時のダウンロードファイル名としてExcelと対になる形とする：`【会社名】勤務実績管理表_YYYYMM_姓名.pdf`（1ユーザー1ファイル）。複数ユーザー分をダウンロードする場合はZIP形式にまとめる。生成後はブラウザへのダウンロードのみで、サーバー側にも永続化しない。

### 5.2 OneDriveアクセス

- 保存先は社内のOneDrive（法人テナント）を使用する。
- **Microsoft Graph APIは使用しない。** 「誰でもアクセス（編集・閲覧）できる」共有設定がなされたOneDriveの共有URL（フォルダ・ファイルの共有リンク）を用いて、ファイルの読み書きを行う方式で開発する。
- **使用する共有URLは、OneDriveの「ルートディレクトリ」1つに対して発行されたものを使用する。** テンプレートファイル・月フォルダ・ユーザーごとのExcelファイルは、すべてこのルートディレクトリ配下（5.1節のフォルダ構成）に格納し、システムはこの1つの共有URLを起点として、配下のファイル・フォルダへアクセスする。
- 共有URL経由でのアクセスとなるため、ユーザー認証・アプリ登録（Azure ADアプリの登録、クライアントID/シークレットの発行等）は不要とする。
- そのため、一般ユーザー・adminともに、システムへのログイン（4.1節の独自ID・パスワード認証）のみでよく、**OneDriveへの個別サインインは発生しない。**
- 共有URLの発行・管理（ルートディレクトリに対する「リンクを知っている全員が編集可能」等の共有設定）は、OneDrive管理者（依頼者側）が事前に行う。開発側は発行された1つの共有URLを設定値として組み込む。

### 5.3 閲覧権限とプレビュー

- OneDrive上の勤怠Excelファイルは、共有URL経由で誰でも閲覧・編集可能な状態にあることを前提として開発する（確定事項）。
- 一方、本システムの権限要件（3.2節）では「一般ユーザーは自分の勤怠のみ閲覧可」としているため、**OneDriveファイル自体へのアクセス制御とは別に、システム（アプリケーション）側でアクセス制御を行う**必要がある。
  - システムの画面経由でアクセスする限りは、一般ユーザーは自分のデータのみが表示され、他ユーザーのデータはアプリケーションレベルで遮断される。
  - OneDrive上のファイルへ、本システムを介さず直接アクセスされた場合の制御は、システムの権限管理の対象外とする（OneDrive側のファイル・フォルダ共有設定は本システムのスコープ外）。
- 勤怠データのプレビュー方法（画面上での表示）は、Excelファイルをブラウザ上で直接開くのではなく、バックエンドがExcelの内容を読み取り、Web上の表形式UI（テーブル）として整形して表示する方式とする。Excelそのものをブラウザ内蔵ビューア等で開く方式は取らない。

### 5.4 ユーザーマスタ

ユーザーマスタで管理する項目は以下のとおり。

| 項目 | 内容 |
|---|---|
| 姓 | 氏名の姓部分 |
| 名 | 氏名の名部分 |
| 社員番号 | 半角数字。3桁・4桁等、ユーザーによって桁数が異なる場合があり、0埋めは行わない。**ログインIDとして使用する** |
| 部署名 | 派遣先部署名（ユーザーごとの固定値、4.2節参照） |
| パスワード | ハッシュ化して保存する（平文保存はしない） |
| 権限区分 | admin／一般ユーザー |

- 氏名は、用途に応じて以下のように結合して使用する（詳細は4.2節参照）。
  - ファイル名（Excel／PDF）：姓名の間にスペースなし（例：`山田太郎`）
  - Excel内の氏名欄（`AH5`）：姓名の間に全角スペース（例：`山田　太郎`）

**管理方法・保存場所**

- ユーザーマスタは、勤怠データ（Excelファイル）とは別に、**システム専用のデータストア**で管理する。OneDrive上のExcelファイルの一部として管理することはしない（勤怠データとマスタデータの責務を分離するため）。
- 実装方式（DB、JSONファイル等）は、4.8節のロック状態管理データストアと同様、実装のしやすさを優先して選定してよい。ただし、パスワードは必ずハッシュ化して保存し、平文を保持しない。
- 保存場所は、勤怠Excel群と同じOneDrive上ではなく、**アプリケーションサーバー側（クラウド環境のストレージ、または同一DB内）**に置くことを想定する。OneDriveは共有URLを介して誰でもアクセス可能な前提（5.2節）のため、パスワード等の機微情報をOneDrive上に置くことは避ける。ロック状態管理データ（4.8節）も同様にアプリケーションサーバー側に保存し、ユーザーマスタと同一のデータストアにまとめるか、別に分けるかは実装のしやすさで選定してよい。

**ユーザーマスタの操作範囲**

| 操作 | 一般ユーザー | admin |
|---|---|---|
| 自分のパスワード変更 | ○（**全ユーザーが自分自身のパスワードを変更できる**） | ○ |
| 自分以外のユーザー情報の追加・編集・削除 | × | ○ |
| 自分の氏名・社員番号・部署名等の変更 | × | ○（本人からの依頼を受けてadminが変更） |

- パスワード変更は、一般ユーザー・adminを問わず、**全ユーザーが自分自身のアカウントに対して行える**機能とする（ログイン後の設定画面等から変更可能とする）。
- 氏名・社員番号・部署名・権限区分の変更は、引き続きadminのみが行える。

**パスワードポリシー**

- 文字数：最小8文字以上、最大は実装のしやすさを優先して問わない（目安：64文字程度まで）。
- 使用可能文字：半角英大文字・半角英小文字・半角数字・一部の半角記号（`! # $ % & * + - . / : = ? @ ^ _`等）を許可する。全角文字・制御文字・スペースは使用不可とする。
- 最低文字種類：半角英大文字・半角英小文字・半角数字のうち、**2種類以上**を組み合わせることを必須とする（記号は任意）。
- 上記ポリシーは新規登録時・パスワード変更時のいずれにも適用し、フロントエンド・バックエンド双方でチェックする。

### 7.4 勤怠入力・閲覧画面（一般ユーザー）詳細

**基本フロー**

1. ユーザーが対象年月を選択する。
2. システムは対象月のExcelファイル（`原本`シート）をOneDriveから読み込み、**現在保存されている内容をそのままプレビュー（読み取り専用のテーブル表示）として表示する。**
   - 対象月のファイルがまだ存在しない場合は、4.2節のとおりテンプレートから新規生成したうえで、その（空の）内容をプレビュー表示する。
3. ユーザーが編集操作（「編集する」ボタン等）を行うと、テーブルが編集可能な状態に切り替わる。
4. 入力・修正を行い、保存操作を行うとバリデーションを実施したうえでExcelファイルへ反映し、OneDriveへ書き戻す。
5. 保存後は再度プレビュー（読み取り専用）表示に戻る。

**構成要素**

| 要素 | 内容 |
|---|---|
| ヘッダー | 対象年月の表示・切り替え（前月／翌月、または月選択プルダウン）、氏名・社員番号の表示、ロック状態の表示、ヘルプボタン |
| ヘルプボタン | 押下すると、`記入例`シートの内容を読み取り専用のプレビュー（ポップアップ等）で表示する。入力ルールに迷った際にいつでも参照できる |
| プレビュー表示 | 月選択直後に表示される、現在保存されている内容の読み取り専用テーブル |
| 編集切り替え | 「編集する」等の操作により、テーブルを編集可能な状態に切り替える |
| 入力テーブル（編集時） | 1日1行。列構成は下記「テーブルの画面構成」を参照 |
| バリデーション表示 | 入力内容に問題がある行はセル・行を強調表示し、エラーメッセージを表示 |
| 保存ボタン | 入力内容をまとめて保存（バックエンド経由でExcelへ反映）。処理中はボタンを無効化し多重送信を防止。保存直前にロック状態・他者更新の有無を再確認する（13章参照） |
| ロック中の表示 | ロックされている月はプレビュー表示のみとなり、「編集する」操作自体が無効化される。「この月はロックされています」等のメッセージを表示。プレビュー閲覧自体は引き続き可能 |

**テーブルの画面構成（フロントUI ⇔ Excel `原本`シートの対応）**

フロントエンドUIのテーブルは、**Excel（`原本`シート）の列配置とは異なる、独自の列順**で構成する。Excel側は日付・曜日・休暇種類・始業時間・終業時間・離業時間・自社工数内容などの項目が離れた列（D・N・Q・AC・APなど）に点在しているが、フロントUIでは1つのテーブル内にこれらを隙間なく並べ、視認性を優先したレイアウトとする。

| # | フロントUIのテーブル列（左から） | 対応するExcel（`原本`シート）上の位置 | 表示・入力形式 |
|---|---|---|---|
| 1 | 日付 | `B`列 | 自動表示（システムが対象月の日数に応じて生成、編集不可） |
| 2 | 曜日 | 日付から自動算出（Excel上は`B`列の日付から導出） | 自動表示（編集不可） |
| 3 | 休暇種類 | `D`列（`D14:D44`） | プルダウン選択（4.3節の11区分） |
| 4 | 始業時間 | `N`列 | 時刻入力（4.3節の入力UI・1分単位） |
| 5 | 終業時間 | `Q`列 | 時刻入力（4.3節の入力UI・1分単位） |
| 6 | 離業時間 | `AC`列 | 時間入力 |
| 7 | 自社工数内容 | `AP`列 | フリーテキスト |

- フロントUIのテーブルは、月の日数分（例：6月なら30行）を1画面のスクロール可能なテーブルとして表示する。Excel上で非表示となる存在しない日付（2月30日等）は、フロントUIのテーブルにもそもそも表示しない。
- 上記の「フロントUIのテーブル列」の並び順・体裁は要求仕様レベルの想定であり、実装時に見やすさの観点で列順・表示形式（例：始業時間と終業時間を1セルにまとめて表示する等）を調整してよい。ただし、Excel上の格納先セル（`D`・`N`・`Q`・`AC`・`AP`列）との対応関係は変えない。

**休暇種類による入力欄の制御**

- フロントUIの休暇種類欄（Excel上は`D`列に対応）は必須選択ではない。平日であれば、休暇種類欄を選択しなくても始業時間欄・終業時間欄は有効。
- 休暇種類欄で「有休」「長期連休」「特別休暇」「欠勤」「振替休暇」を選択した場合、始業時間欄・終業時間欄を自動的に無効化（グレーアウト）する。**既に始業時間・終業時間が入力済みの状態で、これらの休暇種類へ変更しようとした場合も同様にエラーとして扱う**（4.6節ルール3の逆方向ケース）。
- 曜日が「土」「日」の行は、原則として始業時間欄・終業時間欄を無効化する。ただし、休暇種類欄に区分（例：休日出勤、振替出勤等）が選択されている場合は例外的に入力欄を有効化する。
- 「午前半休」「午後半休」の場合は、半日分の勤務時間のみ入力可能とする。

**始業時間・終業時間・離業時間の入力UI**

- **時刻の入力は「時」と「分」を別々の入力要素（プルダウン等）で受け付ける方式とし、`9:30`のようなコロン区切りのテキストをユーザーが直接タイプする形式は採用しない。**
- 「分」は**1分単位**で選択できることを必須とする（5分刻み等の丸めは行わない）。
- この方式により、フロントの入力構造自体がExcelの記述ルール（`9:30`形式、半角数字、先頭ゼロなし）と一致した値のみを生成するため、**バックエンド側での形式変換処理は不要**となる。
- 離業時間についても、始業時間・終業時間と同様に時・分を別入力要素で受け付け、1分単位で指定できるものとする。

**バリデーションエラーの表示例（リアルタイム表示）**

- バリデーションエラーは、保存操作を待たず、入力・選択の都度**リアルタイムに**検知して表示する。
- 日付が空欄の行に休暇種類欄・始業時間欄・終業時間欄のいずれかを入力しようとした → 該当セルを警告色で表示し、「この行には入力できません」等のメッセージを表示
- 休暇区分（有休／長期連休／特別休暇／欠勤／振替休暇）を選択した日に始業時間・終業時間が入力されている → 該当行を警告色で表示
- 始業時間・終業時間が入力済みの行で、休暇区分（有休／長期連休／特別休暇／欠勤／振替休暇）を選択した → 同様に該当行を警告色で表示（入力の順序を問わない）
- 休日（土・日）で休暇種類欄が未選択のまま始業時間・終業時間が入力されている → 該当行を警告色で表示し、「休日に稼働時間が入力されています」等のメッセージを表示

### 7.5 勤怠閲覧・編集画面（admin用）

- adminはユーザー選択欄・月選択欄から任意の組み合わせを選ぶと、7.4節と同様に**まず現在の保存内容をプレビュー（読み取り専用）表示する。**
- プレビューから編集操作に切り替えることで、そのまま編集も行える（7.4節の入力画面と同様のUI・バリデーションを適用）。
- **ロック状態に関わらず、常に編集操作へ切り替えることができる**（一般ユーザーと異なり、ロック中でも「編集する」操作が無効化されない）。
- 保存操作により、OneDrive上のExcelファイルへ反映される。保存直前には、一般ユーザーによる同時更新がないかを再確認する（13章参照）。競合が検知された場合は保存を中断し、最新内容を再取得したうえで確認を求める。

### 7.6 PDF出力画面（admin）

- ユーザーを1名または複数名選択し、対象月を指定してPDFを生成する。
- 出力範囲：`J1:AQ50`、A4縦。
- PDFは1ユーザー1ファイルとして生成する。
- 単一ユーザー選択時はPDFを直接ダウンロード、複数ユーザー選択時はZIPファイルにまとめてダウンロードする。**OneDrive上への保存は行わない。**
- 主に月次締め処理時に利用する画面と位置付ける。

### 7.7 ロック管理画面（admin）

- 対象月を選択すると、その月の全ユーザーのロック状態一覧（ユーザー名・ロック中／編集可能）が表示される。
- 「まとめてロック」ボタンで一括ロック。
- 各ユーザー行に「ロック」「解除」の個別操作ボタンを配置。

## 9. 処理フロー（勤怠入力の例）

1. 一般ユーザーがID（社員番号）・パスワードでログインする。
2. 対象月を選択する。
3. Streamlitアプリが該当ユーザー・該当月のExcelファイルをOneDriveから取得する。該当月のフォルダ・ファイルがまだ存在しない場合は、この時点でフォルダ作成・テンプレートからのファイル新規作成を行いOneDriveへ保存する（競合対策は13章参照）。既に存在する場合はそのファイルを使用する。
4. 取得した内容を、まず読み取り専用のプレビューとして表示する。
5. ロック状態を確認する。ロック中でなければ「編集する」操作が可能、ロック中であれば編集操作を無効化し、プレビュー表示のみとする。
6. ユーザーが編集操作を行い、休暇種類・始業時間・終業時間・離業時間・自社工数内容を入力・修正する。入力内容はリアルタイムにバリデーションされ、問題があればその場でエラー表示する。
7. 保存操作を行う。保存直前に、システムはロック状態と対象ファイルの最新状態を再確認する（13章の排他制御）。他者による更新やロックが検知された場合は保存を中断し、エラーメッセージを表示する。
8. 問題がなければ、Excelファイルの該当セルを更新し、OneDriveへ書き戻す。**このとき、対象セルの値のみを更新し、元のExcelファイルの書式（フォント・罫線・条件付き書式等）は崩さない。** 保存後は再度プレビュー表示に戻る。

3. アプリがOneDriveから該当Excelファイルを取得する。
4. Excel→PDF変換処理を行う。
5. PDFをダウンロードする。

## 11. ロック管理フロー（admin）

1. adminがログインする。
2. 対象月を選択する。
3. 「まとめてロック」を選択した場合：該当月の全ユーザーファイルをロック状態にする。
4. 「個別にロック」を選択した場合：ユーザーを指定してロック状態にする。
5. 「個別に解除」を選択した場合：ロック済みユーザーを指定して解除する。
6. ロック状態はロック状態管理データストアへ即時反映される。既に対象ユーザーが編集画面を開いている場合でも、開いている画面上の編集操作を強制終了させることはしない。ただし、当該ユーザーが保存操作を行った時点でロック状態が再チェックされ、保存が拒否される（13.2節参照）。

## 12. admin編集フロー

1. adminがログインする。
2. 対象ユーザー・対象月を選択する。
3. アプリがOneDriveから該当Excelファイルを取得し、まず読み取り専用のプレビューとして表示する（ロック状態に関わらず表示可能）。
4. adminが編集操作を行うと、編集可能なテーブルに切り替わる（ロック状態に関わらず常に編集操作へ切り替え可能）。
5. adminが内容を編集する。入力内容はリアルタイムにバリデーションされ、問題があればその場でエラー表示する。
6. 保存操作を行う。保存直前に、システムは対象ファイルの最新状態を再確認する（13章の排他制御）。一般ユーザーが同時に同じファイルを更新していた場合は、その旨を通知し、最新内容を再取得したうえで保存の可否を判断する。
7. 問題がなければ、Excelファイルの該当セルを更新し、OneDriveへ書き戻す。**このとき、対象セルの値のみを更新し、元のExcelファイルの書式（フォント・罫線・条件付き書式等）は崩さない。** 保存後は再度プレビュー表示に戻る。

## 13. 排他制御・同時アクセス時の競合対策

本システムはブラウザ経由で複数ユーザー（一般ユーザー最大10名弱＋admin1名を想定）が同時にアクセスする。以下、想定される競合シナリオごとに対策を明記する。これらは4章（機能要件）・7章（画面要件）の記述と矛盾しないよう整合させている。

### 13.1 一般ユーザーとadminが同一ファイルを同時に編集した場合

- 想定シナリオ：一般ユーザーが自分の勤怠を編集・保存しようとしている最中に、adminが同じユーザー・同じ月のファイルを編集・保存する（またはその逆）。
- 対策：
  - 保存操作の直前に、システムは対象ファイルの最新状態（OneDrive上の現在の内容、および何らかの更新識別子＝更新日時やバージョン情報等）を再取得し、**自分がプレビュー取得した時点の内容から他者によって更新されていないか**を確認する（いわゆる楽観的排他制御）。
  - 他者による更新が検知された場合、保存は中断し、「他のユーザーによって内容が更新されています。最新の内容を確認してから再度編集してください」等のメッセージを表示し、最新内容を再取得したプレビューへ戻す。編集内容は破棄せず、可能であれば入力途中の内容を画面上に保持し、ユーザーが差分を確認できるようにする（実装詳細は開発時に検討）。
  - この楽観的排他制御により、無条件の上書き（後勝ち）によるデータ消失を防ぐ。

### 13.2 一般ユーザーが編集中に、adminがロックをかけた場合

- 想定シナリオ：一般ユーザーが編集モードで入力作業をしている最中に、adminがロック管理画面から当該ユーザー・当該月をロックする。
- 対策：
  - ロック操作はロック状態管理データストア（4.8節）に即座に反映されるが、**一般ユーザー側の画面は、既に開いている編集モードの入力操作自体を即座に強制終了させることはしない**（画面を予告なく閉じたり、入力中の内容を消去したりしない）。
  - ただし、一般ユーザーが**保存操作**を行った時点で、システムはロック状態を必ず再チェックする。ロック済みであることが判明した場合、保存は行わず、「この月はロックされました。入力内容は保存できません」等のメッセージを表示する。入力中の内容は画面上に残し、ユーザーが必要であれば内容をメモ・再入力の参考にできるようにする。
  - 次にユーザーが画面を再読み込みする、または対象月を選び直した場合は、通常どおりロック中の表示（プレビューのみ、編集操作不可）に切り替わる。

### 13.3 複数一般ユーザーが同時に別々のファイルを操作する場合

- 各一般ユーザーは自分専用のExcelファイルのみを操作するため、ユーザー間でのファイル競合は基本的に発生しない。
- ただし、同一月フォルダが未作成の状態で複数ユーザーが初回アクセスするケースは、4.2節「フォルダ作成の競合対策」のとおり、冪等な作成処理で対応する。

### 13.4 admin機能（ロック管理・PDF出力・ユーザーマスタ管理）の競合

- adminアカウントは1名（3.1節）のため、admin操作同士の競合は基本的に想定しない。ただし、同一adminが複数タブ・複数端末から同時に操作するケースも考慮し、ロック状態・ユーザーマスタの更新については13.1節と同様の楽観的排他制御（更新前に最新状態を確認する）を適用する。

### 13.5 全体方針のまとめ

| 競合パターン | 対策方針 |
|---|---|
| 一般ユーザー×admin：同一ファイルへの同時編集・保存 | 保存直前に最新状態を再確認する楽観的排他制御。競合時は保存を中断し、最新内容を再取得させる |
| 一般ユーザー編集中のadminロック | 編集中の操作は強制終了しない。保存時にロック状態を再チェックし、ロック済みなら保存を拒否する |
| 複数ユーザーの月フォルダ同時作成 | フォルダ・ファイルの存在チェック→作成処理を冪等にし、重複作成時も1つに収束させる |
| admin操作同士の競合（同一adminの複数タブ等） | 一般ユーザーと同様の楽観的排他制御を適用 |
| ブラウザからの多重クリック・多重送信全般 | 保存等の操作ボタンは処理中に無効化し、同一操作の多重送信を防止する |

## 14. 既存Excelファイルの仕様調査結果（参考情報）

以下を確認した。

- シート構成：`原本`（実データ入力シート）、`変更履歴`、`記入例`（保護済み・入力例シート）
- 主要セル
  - `C8`：対象月初日
  - `O5`：社員番号
  - `AH4`：部署名
  - `AH5`：氏名
  - `D14:D44`：休暇種類（入力規則：リスト選択、参照範囲 `AY14:AY24`）
  - `N`列：出勤時間、`Q`列：退勤時間、`AC`列：離業時間、`AP`列：自社工数内容
- 休暇種類リスト（`AY14:AY24`）：有休／午前半休／午後半休／長期連休／特別休暇／欠勤／振替休暇／休日出勤／振替出勤／稼働日／休日
- 条件付き書式：D14:D44・N9:S39・K9:AP39 等の範囲に対し、曜日区分（土＝AY10／日＝AY11）や休暇種別との組み合わせによる複数の警告ルールが設定されている（該当時にセルが赤色等で塗りつぶされる）。
- `原本`シートはシート保護がかかっていない（`protection=False`）一方、`記入例`シートは保護されている（`protection=True`）。実運用のテンプレートでは保護設定を要確認。

## 15. 既存運用からの移行方針

本システム稼働後、既存のExcelテンプレート（原本・記入例・変更履歴シート）を用いた手動配布・運用は廃止する。ただし、これまでの入力ルールや休暇種類の説明等、ユーザーが参照してきた情報は失われないよう、システム内にヘルプページ（利用ガイド等）を設け、必要な情報を引き続き参照できるようにする。
