# 単体テスト仕様書：SC-05 ロック管理画面

対象画面：`_pages/04_admin_lock_management.py`
確認方法：ブラウザ操作　→　画面上のロック状態表示、および他画面（SC-02/SC-03）での反映結果を確認する

## 1. 画面表示・一覧

| No. | 操作手順 | 期待結果 | 結果 |
|---|---|---|---|
| 1-1 | adminでログインし、ロック管理画面を開く | 対象年月プルダウンと、その月の全ユーザーのロック状態一覧（氏名・社員番号・状態・操作ボタン）が表示される | ok |
| 1-2 | 一般ユーザーが1人も登録されていない状態で画面を開く | 「対象ユーザーが登録されていません。」と表示される | ok |
| 1-3 | 一度もロック操作されていない月を選択する | 全ユーザーが「● 未ロック」（緑）表示になっている | ok |

## 2. 個別ロック

| No. | 操作手順 | 期待結果 | 結果 |
|---|---|---|---|
| 2-1 | 未ロックのユーザー行にある「ロック」ボタンを押す | そのユーザーの行が即座に「● ロック中」（赤）表示に切り替わり、操作ボタンが「解除」に変わる | ok |
| 2-2 | 2-1の後、一般ユーザー本人が該当月の勤怠入力画面を開く | 「● ロック中」バッジが表示され、「編集する」ボタンが押せなくなっている | ok |
| 2-3 | 2-1でロックした行以外のユーザーの状態を確認する | 変化していない（未ロックのまま） | ok |

## 3. 個別解除

| No. | 操作手順 | 期待結果 | 結果 |
|---|---|---|---|
| 3-1 | ロック中のユーザー行にある「解除」ボタンを押す | そのユーザーの行が即座に「● 未ロック」表示に切り替わり、操作ボタンが「ロック」に変わる | ok |
| 3-2 | 3-1の後、一般ユーザー本人が該当月の勤怠入力画面を開く | 「● 未ロック」バッジが表示され、「編集する」ボタンが押せるようになる | ok |
| 3-3 | 解除操作を行ったあと、一括解除に相当するボタンや機能が画面上に存在しないことを確認する | 「まとめて解除」のようなボタンは存在せず、解除は個別操作のみで行える | ok |

## 4. まとめてロック

| No. | 操作手順 | 期待結果 | 結果 |
|---|---|---|---|
| 4-1 | 「まとめてロック」ボタンを押す | 確認ダイアログ（「対象年月 の全ユーザーをロックします。よろしいですか？」）が表示される | ok |
| 4-2 | 確認ダイアログで「キャンセル」を押す | ダイアログが閉じ、ロック状態一覧に変化がない | ok |
| 4-3 | 確認ダイアログで「ロックする」を押す | ダイアログが閉じ、「N名をロックしました。」というメッセージが表示され、一覧の全ユーザーが「● ロック中」に切り替わる | ok |
| 4-4 | 4-3の後、一般ユーザー側で該当月にアクセスする（複数ユーザーで確認） | 全ユーザーとも「編集する」ボタンが押せなくなっている | ok |
| 4-5 | 一部ユーザーが既にロック中の状態で「まとめてロック」を実行する | 既にロック中のユーザーも含め、全ユーザーが（変化なく）ロック中のまま維持される | ok |

## 5. 対象年月の切り替え

| No. | 操作手順 | 期待結果 | 結果 |
|---|---|---|---|
