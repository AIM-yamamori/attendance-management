# 単体テスト仕様書：ロック状態と編集可否の排他関係（横断シナリオ）

対象画面：`_pages/01_attendance_input.py`、`_pages/02_admin_attendance_edit.py`、`_pages/04_admin_lock_management.py`
確認方法：複数画面を跨いだブラウザ操作　→　各画面での「編集する」ボタンの活性状態・保存可否を確認する

## 1. 未ロック時の基本状態

| No. | 操作手順 | 期待結果 | 結果 |
|---|---|---|---|
| 1-1 | 未ロックの月・ユーザーで、一般ユーザー画面の「編集する」ボタンの状態を確認する | 押せる状態（活性）になっている | ok |
| 1-2 | 同じ月・ユーザーで、admin側の勤怠閲覧・編集画面の「編集する」ボタンの状態を確認する | 押せない状態（非活性）になっている | ok |

## 2. ロック中の基本状態

| No. | 操作手順 | 期待結果 | 結果 |
|---|---|---|---|
| 2-1 | ロック管理画面で対象ユーザー・月をロックする | ロック状態一覧が「● ロック中」に切り替わる | ok |
| 2-2 | 2-1の直後、一般ユーザー画面で同じ月を開く | 「編集する」ボタンが押せない状態になっている | ok |
| 2-3 | 2-1の直後、admin側の勤怠閲覧・編集画面で同じユーザー・月を開く | 「編集する」ボタンが押せる状態になっている | ok |

## 3. ロック解除後の状態

| No. | 操作手順 | 期待結果 | 結果 |
|---|---|---|---|
| 3-1 | ロック中の状態から、ロック管理画面で「解除」を押す | 状態一覧が「● 未ロック」に切り替わる | ok |
| 3-2 | 3-1の直後、一般ユーザー画面で該当月を開く | 「編集する」ボタンが再び押せる状態になっている | ok |
| 3-3 | 3-1の直後、admin側画面で該当ユーザー・月を開く | 「編集する」ボタンが再び押せない状態になっている | ok |

## 4. 一般ユーザー編集中のロック（境界タイミング）

| No. | 操作手順 | 期待結果 | 結果 |
|---|---|---|---|
| 4-1 | 一般ユーザーが未ロックの月で編集モードに入り、入力途中の状態にする | 編集フォームに入力内容が表示されたままになっている | ok |
| 4-2 | 4-1の状態のまま、別画面（admin）でその月・ユーザーをロックする | ロック管理画面上ではロック中に切り替わる | ok |
| 4-3 | 4-1の一般ユーザー画面（まだ再読み込みしていない）を確認する | 編集フォームは強制終了されず、入力していた内容がそのまま画面に残っている | ok |
| 4-4 | 4-3の状態で「保存する」を押す | 保存が実行されず、「この月はロックされました。入力内容は保存できません。」と表示される。入力内容は画面上に残る | ok |
| 4-5 | 4-4の後、対象月を選び直す（再読み込みする） | 「● ロック中」表示になり、「編集する」ボタンが押せなくなる | ok |

## 5. admin編集中のロック解除（境界タイミング）

| No. | 操作手順 | 期待結果 | 結果 |
|---|---|---|---|
| 5-1 | adminがロック中の月で編集モードに入り、入力途中の状態にする | 編集フォームに入力内容が表示されている | ok |
| 5-2 | 5-1の状態のまま、別画面（ロック管理画面）でその月・ユーザーのロックを解除する | ロック管理画面上では未ロックに切り替わる | ok |
| 5-3 | 5-1のadmin編集画面（まだ再読み込みしていない）を確認する | 編集フォームは強制終了されず、入力内容がそのまま残っている | ok |
| 5-4 | 5-3の状態で「保存する」を押す | 保存が実行されず、「この月のロックが解除されています。保存できません。」と表示される | ok |
| 5-5 | 5-4の後、対象ユーザー・月を選び直す | 「● 未ロック」表示になり、「編集する」ボタンが押せなくなる | ok |

## 6. 一般ユーザー・admin同時編集不可の確認（構造的排他性）

| No. | 操作手順 | 期待結果 | 結果 |
|---|---|---|---|
| 6-1 | 未ロックの月で一般ユーザーが「編集する」を押せる状態を確認しつつ、同時にadmin側でも同じ月・ユーザーの「編集する」ボタンの状態を確認する | 一般ユーザー側は活性、admin側は非活性であり、両者が同時に編集可能な状態には決してならない | ok |
| 6-2 | ロック中の月で、同様に両画面のボタン状態を確認する | admin側が活性、一般ユーザー側が非活性であり、こちらも両者が同時に編集可能にはならない | ok |

## 7. まとめてロック実行時の一括反映確認

| No. | 操作手順 | 期待結果 | 結果 |
|---|---|---|---|
| 7-1 | 複数の一般ユーザーが未ロックの月をそれぞれ編集可能な状態で、admin側から「まとめてロック」を実行する | 全ユーザーが一斉にロック中の状態へ切り替わる | ok |
| 7-2 | 7-1の後、各一般ユーザーが自分の勤怠画面を開く | 全員とも「編集する」ボタンが押せない状態になっている | ok |
