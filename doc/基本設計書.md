# 1. はじめに

## 1.1 本書の位置づけ
本書は「勤怠管理システム 要件定義書 v0.14」に基づき、実装に必要となるシステム構成、画面、DB、内部モジュール、Excel連携、バリデーション、ロック、PDF出力、認証等の方式を定義する。

## 1.2 基本方針
- Webブラウザから利用する。
- StreamlitによるPython一体型アプリケーションとする。
- ユーザー情報・ロック状態・システム設定はSQLiteで管理する。
- 勤怠データ本体は月次Excelファイルとして管理する。
- ExcelファイルはOneDrive上で管理する想定とする。
- **OneDrive連携**: Microsoft Graph API の `/shares` エンドポイントを使用し、クライアントクレデンシャルフローで認証を行う。
- **Excel操作**: 読み取り時は `data_only=True` を使用。書き込み時は書式を維持するためセルの値のみを更新する。
- **権限分離**: 一般ユーザーとadminの編集可能状態を「ロック」によって構造的に排他的にする。
- パスワードはbcryptでハッシュ化し、平文では保存しない。

# 2. システム全体構成

## 2.1 論理構成

```text
┌──────────────────────────────┐
│          Webブラウザ          │
│   一般ユーザー / admin 共通    │
└──────────────┬───────────────┘
               │ HTTPS
               ▼
┌──────────────────────────────────────────┐
│             Streamlit アプリ             │
│                                          │
│  ┌────────────┐   ┌──────────────┐      │
│  │ 画面レイヤー │ → │ Service層     │      │
│  │ _pages/    │   │ services/    │      │
│  └────────────┘   └──────┬───────┘      │
│                           │              │
│                    ┌──────┴──────┐       │
│                    │ Adapter層   │       │
│                    │ adapters/   │       │
│                    └───┬─────┬───┘       │
└────────────────────────┼─────┼───────────┘
                         │     │
              ┌──────────┘     └────────────┐
              ▼                             ▼
        ┌─────────────┐              ┌─────────────┐
        │ SQLite      │              │ OneDrive    │
        │ app.db      │              │ 月次Excel    │
        └─────────────┘              └─────────────┘
                                            ▲
                                            │
                                    現在は疑似OneDrive
                                    （ローカルディレクトリ）
```

## 2.2 レイヤー構成
- **画面レイヤー**: Streamlitによる画面表示、入力受付、結果表示。
- **Service層**: 認証、ユーザー管理、ロック、勤怠、PDF等の業務処理。
- **Adapter層**: DB、OneDrive、Excel等の外部リソースとの入出力。
- **DB**: ユーザーマスタ、ロック状態、システム設定。
- **OneDrive**: 月次Excel、テンプレートExcel。

## 2.3 責務分離
画面側に業務ロジックを直接記述せず、可能な限りService層へ委譲する。

## 3.1 画面一覧

|---|---|---|---|

| SC-08 | 記入例ヘルプ | 一般ユーザー・admin | SC-02等から表示 |

## 3.3 二重のアクセス制御
- **Navigationによる制御**: `st.navigation()` を利用し、ログイン状態およびroleに応じて動的にサイドバーを構成。
- **ページ内権限チェック**: 各ページ冒頭で `session_service.require_admin()` 等の関数を実行。
- **ログイン画面の特殊処理**: ログイン画面自体を `st.Page(..., position="hidden")` として登録し、ログイン前でも `st.navigation` を呼び出すことで、Streamlitの「pages/ディレクトリ自動検出」を確実に無効化する。

```text

```

OneDriveやサーバーへ恒久保存せず、生成したバイナリをダウンロード対象として扱う。

- 全ユーザーのロック状態表示

### 制約

- 一括ロック：あり
- 一括解除：なし
- 個別解除：あり

### 状態

```text
未ロック → ロック
ロック中 → 解除
```

### 一覧

- 社員番号
- 姓
- 名
- 部署名

### 新規追加

入力項目：

- 姓

- 部署名

### 編集

変更可能：

- 姓

### 削除

### パスワード再設定

adminが対象ユーザーのパスワードを再設定する。

一般ユーザー・admin共通。

入力：

## 4.1 DB方式
SQLiteを使用。Docker環境ではホストの `./data` を `/app/data` へマウント。

## 4.2 テーブル
- `users`: 社員番号（ID）、姓名、部署名、パスワードハッシュ、権限区分。
- `locks`: 対象月、ユーザーID、ロック状態（0:未ロック、1:ロック中）、更新日時。
- `settings`: システム設定（`service_start_month` 等）。

# 5. 内部モジュール設計

## 5.1 構成

```text
services/
├── auth_service.py
├── session_service.py
├── user_service.py
├── lock_service.py
├── attendance_service.py
├── validation_service.py
├── pdf_service.py
└── settings_service.py

adapters/
├── onedrive_adapter.py
└── db_adapter.py
└── excel_adapter.py
```

## 5.2 auth_service

責務：

- ログイン認証
- パスワードハッシュ化
- パスワード検証
- 本人パスワード変更
- adminによるパスワード再設定

主要関数：

```python
authenticate(employee_id, password)
change_password(employee_id, current_password, new_password)
reset_password_by_admin(employee_id, new_password)
```

## 5.3 session_service
- **セッションの完全な破棄**: ログアウト時、`st.session_state.clear()` を実行。これにより、`st.navigation` の内部状態（選択していたページ等）を含めて確実にリセットし、サイドバーの残像等の不具合を防止する。

## 5.6 attendance_service
- **月次ファイル生成**: ユーザーの初回アクセス時に、存在しなければテンプレートから生成（冪等な処理）。
- **データの読み込み**: `openpyxl` の `data_only=True` を使用し、計算結果を読み取る。
- **データの保存**: 数式を保持するため、対象セルの `.value` のみを取り出し、書き込み時は `data_only=True` を使わずに反映する。

## 5.7 validation_service
- 入力値のリアルタイムバリデーション。時刻形式（H:MM）のサニタイズ（全角→半角変換等）を含む。

# 6. Excel・OneDrive連携設計

## 6.2 OneDriveアクセス方式（確定仕様）
- **技術方式**: **Microsoft Graph API の `/shares` エンドポイント**を使用。
- **認証方式**: **クライアントクレデンシャルフロー**を採用。
- **権限**: `Files.ReadWrite.All`（アプリケーション権限）を必要とする。
- **フォールバック**: `ONEDRIVE_CLIENT_ID` 等が未設定の場合は、`ONEDRIVE_LOCAL_ROOT` を使用したローカル疑似OneDriveとして利用する。

## 6.3 OneDrive Adapter
- 外部には「フォルダ・ファイルの存在確認」「ダウンロード」「アップロード」の5操作のみを公開。

## 6.4 冪等性
- フォルダ・ファイルの存在確認を行い、存在しない場合のみ作成する。

## 6.5 Excelテンプレート
- コピー対象：`原本`、`記入例`。`変更履歴` はコピーしない。

## 6.6 Excelセル対応表

| 項目 | セル |
|---|---|
| 対象月 | C8 |
| 社員番号 | O5 |
| 部署名 | AH4 |
| 氏名 | AH5 |
| 日付 | B14:B44 |
| 曜日 | C列等、日付から算出 |
| 休暇種類 | D14:D44 |
| 始業時間 | N列 |
| 終業時間 | Q列 |
| 離業時間 | AC列 |
| 自社工数内容 | AP列 |
| 休憩時間 | G列 |
| 実働時間 | S列 |
| 超勤 | U列 |
| 休日出勤 | W列 |
| 深夜 | Y列 |
| 深夜開始時間 | AA列 |

## 6.7 Excel書き込み方針
- **書式の保持**: 書き込み時は対象セルの `.value` のみ更新。罫線・条件付き書式・数式を維持する。
- **時刻データの変換**: フロント側の数値（時・分）から Excel用の `"H:MM"` 形式の文字列への変換を `excel_adapter.py` に集約する。

# 7. バリデーション設計

## 7.1 基本方針

入力時と保存時の二重チェックとする。

```text
画面入力時
 ↓
行単位チェック

保存時
 ↓
月全体チェック
 ↓
保存直前に再チェック
```

## 7.2 主なルール

### VAL-01

日付が存在しない行には休暇種類を入力できない。

### VAL-02

日付が存在しない行には始業・終業時間を入力できない。

### VAL-03

以下の休暇区分では始業・終業時間を入力できない。

```text
有休
長期連休
特別休暇
欠勤
振替休暇
```

### VAL-04

土日かつ休暇種類が未選択で、始業・終業時間が入力されている場合はエラー。

### VAL-05

土日でも休暇種類が選択されている場合は、VAL-04のエラー対象外とする。

例：

```text
土曜日 + 休日出勤
```

などは入力可能。

## 7.3 UIによる予防

以下の場合、始業・終業入力をdisabledにする。

- 特定の休暇区分
- 土日かつ休暇種類未選択

ただし、入力済みの時刻がある状態で休暇区分へ変更した場合は、変更を禁止するのではなくエラーとして検出する。

## 7.4 時刻形式

```regex
^([0-9]|1[0-9]|2[0-3]):[0-5][0-9]$
```

例：

```text
9:00    OK
9:30    OK
23:59   OK
09:00   不許可
24:00   不許可
9:60    不許可
```

# 8. 排他制御・ロック設計

## 8.1 基本方針
- 一般ユーザーとadminの編集可能状態を逆にする。
- **一般ユーザー**: 「ロックされていない月」のみ編集可能。
- **admin**: 「ロック中の月」のみ編集可能。
- この設計により、同一ファイルへの同時編集を構造的に防ぐ。

## 8.2 保存直前チェック
- 保存操作の直前に必ず最新のロック状態を再取得し、編集可能状態であれば保存を許可する。

# 9. PDF出力設計
- LibreOfficeによる変換方式を採用。
- `原本`シートの `J1:AQ50` をA4縦1枚に収める。
- 複数名時はZIP化。

# 10. 認証・パスワード設計
- bcryptによるハッシュ化。
- IDが存在しない場合とパスワードが違う場合でエラーメッセージを区別しない（セキュリティ方針）。
- パスワードポリシー：8文字以上、2種類以上の文字種。

---

# 11. エラーハンドリング方針

## 11.1 基本方針

画面にはユーザーが理解できるエラーを表示する。

内部例外の詳細をそのままユーザーへ表示することは避ける。

## 11.2 主なエラー

| エラー | 対応 |
|---|---|
| OneDrive/ファイル取得失敗 | 読み込み・保存失敗を表示 |
| Excel形式異常 | 管理者への連絡を案内 |
| SQLiteエラー | システムエラーを表示 |
| バリデーションエラー | 行単位で表示し保存中止 |
| ロック競合 | 保存中止、入力内容は保持 |
| PDF生成失敗 | PDF生成失敗を表示 |

## 11.3 ログ

要件上、監査ログ機能は設けない。

アプリケーションとして永続的な操作履歴・障害ログを保持しない。

ただしDockerや実行環境が標準で出力する一時的なコンソールログ等は除く。

# 18. 設計上の重要ポイントまとめ
1.  **Streamlit一体型アプリ**として構築する。
2.  **画面・業務ロジック・外部連携を分離**する。
3.  **セッション管理の完全なクリア**（`st.session_state.clear()`）を徹底する。
4.  **ユーザー・ロック・設定はSQLite**で管理する。
5.  **勤怠データ本体はExcelファイル**で管理する。
6.  **一般ユーザーとadminの編集権限を構造的に排他的**にする。
7.  **OneDrive連携はGraph API `/shares` とクライアントクレデンシャル**を用いる。
8.  **Excelの書式を崩さない**ため、書き込み時は `.value` のみ更新する。
9.  **パスワードはbcryptでハッシュ化**する。
10. **PDFはLibreOfficeを利用**する。
11. **Dockerで環境を統一**する。
12. **ページファイル名は英語**で統一する。
13. **時刻入力は H:MM 形式のテキストボックス**とし、サニタイズを行う。
