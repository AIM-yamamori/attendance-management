# 1. はじめに

## 1.1 本書の位置づけ

本書は「勤怠管理システム 要件定義書 v0.14」に基づき、実装に必要となるシステム構成、画面、DB、内部モジュール、Excel連携、バリデーション、ロック、PDF出力、認証等の方式を定義する。

2026-08-19時点では、画面・SQLite・Docker・Excel処理・疑似OneDrive連携等の実装が進んでいるため、本書では実装コードとの整合性も考慮する。

## 1.2 基本方針

- Webブラウザから利用する。
- StreamlitによるPython一体型アプリケーションとする。
- ユーザー情報・ロック状態・システム設定はSQLiteで管理する。
- 勤怠データ本体は月次Excelファイルとして管理する。
- ExcelファイルはOneDrive上で管理する想定とする。
- 現時点の開発では、OneDriveの代わりにローカルディレクトリを疑似OneDriveとして利用する。
- Excelの読み書きにはopenpyxlを使用する。
- PDF出力ではDocker内にLibreOfficeを導入し、ExcelからPDFへの変換を行う方式を現在の実装とする。
- 一般ユーザーとadminが同じ勤怠ファイルを同時編集しないよう、月単位のロック状態で編集権限を分離する。
- パスワードはbcryptでハッシュ化し、平文では保存しない。

# 2. システム全体構成

## 2.1 論理構成

```text
┌──────────────────────────────┐
│          Webブラウザ          │
│   一般ユーザー / admin 共通    │
└──────────────┬───────────────┘
               │ HTTPS
               ▼
┌──────────────────────────────────────────┐
│             Streamlit アプリ             │
│                                          │
│  ┌────────────┐   ┌──────────────┐      │
│  │ 画面レイヤー │ → │ Service層     │      │
│  │ _pages/    │   │ services/    │      │
│  └────────────┘   └──────┬───────┘      │
│                           │              │
│                    ┌──────┴──────┐       │
│                    │ Adapter層   │       │
│                    │ adapters/   │       │
│                    └───┬─────┬───┘       │
└────────────────────────┼─────┼───────────┘
                         │     │
              ┌──────────┘     └────────────┐
              ▼                             ▼
        ┌─────────────┐              ┌─────────────┐
        │ SQLite      │              │ OneDrive    │
        │ app.db      │              │ 月次Excel    │
        └─────────────┘              └─────────────┘
                                            ▲
                                            │
                                    現在は疑似OneDrive
                                    （ローカルディレクトリ）
```

## 2.2 レイヤー構成

| レイヤー | 役割 |
|---|---|
| 画面レイヤー | Streamlitによる画面表示、入力受付、結果表示 |
| Service層 | 認証、ユーザー管理、ロック、勤怠、PDF等の業務処理 |
| Adapter層 | DB、OneDrive、Excel等の外部リソースとの入出力 |
| DB | ユーザーマスタ、ロック状態、システム設定 |
| OneDrive/疑似OneDrive | 月次Excel、テンプレートExcel |

## 2.3 責務分離

画面側に業務ロジックを直接記述せず、可能な限りService層へ委譲する。

例：

```text
画面
  ↓
auth_service.change_password()
  ↓
現在パスワード確認
新パスワードポリシー確認
DB更新
  ↓
結果を画面へ返す
```

これにより、画面側は入力・表示に集中する。

### 入力

- ログインID
- パスワード

### ログインID

| 利用者 | ログインID |
|---|---|
| 一般ユーザー | 社員番号 |

## 3.5 SC-02 勤怠入力・閲覧

### 基本フロー

```text
ログイン
 ↓
対象年月選択
 ↓
勤怠データ取得
 ↓
プレビュー表示
 ↓
編集する
 ↓
入力
 ↓
バリデーション
 ↓
保存
```

### 対象年月

- デフォルト：当月
- 選択可能上限：翌月
- 選択可能下限：`service_start_month`

### プレビュー

読み取り専用で以下を表示する。

- 日付
- 曜日
- 休暇種類
- 始業
- 終業
- 離業
- 自社工数内容
- 休憩
- 実働
- 超勤
- 休日出勤
- 深夜
- 深夜開始時間
- 月間合計

### 編集対象

編集できるのは以下。

- 休暇種類
- 始業時間
- 終業時間
- 離業時間
- 自社工数内容

自動計算項目は編集対象外とする。

### ロック時

```text
プレビュー：可能
編集：不可
```

「この月はロックされています」等の理由を表示する。

- 全ユーザーのロック状態表示

### 制約

- 一括ロック：あり
- 一括解除：なし
- 個別解除：あり

### 状態

```text

```

adminのみ利用可能。

- 名

# 4. データベース設計

## 4.1 DB方式

SQLiteを使用する。

```text
DB_PATH
  ↓
./data/app.db（開発）
/app/data/app.db（Docker）
```

Dockerではホストの`./data`を`/app/data`へマウントする。

## 4.2 テーブル

```text
users
locks
settings
```

## 4.3 users

```sql
CREATE TABLE IF NOT EXISTS users (
    employee_id   TEXT PRIMARY KEY,
    last_name     TEXT NOT NULL,
    first_name    TEXT NOT NULL,
    department    TEXT NOT NULL,
    password_hash TEXT NOT NULL,
    role          TEXT NOT NULL CHECK(role IN ('admin','general')),
    created_at    TEXT NOT NULL,
    updated_at    TEXT NOT NULL
);
```

### role

```text
admin
general
```

adminは固定ID：

```text
admin
```

## 4.4 locks

```sql
CREATE TABLE IF NOT EXISTS locks (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    target_month  TEXT NOT NULL,
    employee_id   TEXT NOT NULL REFERENCES users(employee_id),
    is_locked     INTEGER NOT NULL DEFAULT 0,
    locked_at     TEXT,
    unlocked_at   TEXT,
    updated_at    TEXT NOT NULL,
    UNIQUE(target_month, employee_id)
);
```

### 状態

```text
0 = 未ロック
1 = ロック中
```

### 基本方針

該当月・ユーザーのレコードが存在しない場合は未ロックとして扱う。

## 4.5 settings

```sql
CREATE TABLE IF NOT EXISTS settings (
    key         TEXT PRIMARY KEY,
    value       TEXT NOT NULL,
    updated_at  TEXT NOT NULL
);
```

主な設定：

```text
service_start_month
```

## 4.6 DB接続

`db_adapter.py`がSQLite接続を担当する。

主な機能：

```python
get_connection()
get_cursor()
init_db()
seed_initial_admin()
seed_setting_if_absent()
```

SQLite接続時には外部キー制約を有効化する。

```sql
PRAGMA foreign_keys = ON
```

## 4.7 初期データ

### admin

`employee_id='admin'` が存在しない場合のみ初期adminを作成する。

### service_start_month

設定が存在しない場合のみ初期値を投入する。

これらは複数回実行しても重複しない冪等な初期化とする。

# 6. Excel・OneDrive連携設計

## 6.1 Excelファイル管理

想定するOneDrive構成：

```text
OneDriveルート/
├── 【会社名】勤務実績管理表_テンプレート.xlsx

│   ├── 【会社名】勤務実績管理表_202608_山田太郎.xlsx

└── 202609/
    └── ...
```

## 6.2 現在のOneDrive実装

現時点では実OneDriveではなく、以下を疑似OneDriveとして利用する。

```text
ONEDRIVE_LOCAL_ROOT
        ↓
ローカルディレクトリ
```

例：

```text
./data/onedrive_local/
├── 202608/
│   └── 勤務実績管理表_202608_山田太郎.xlsx
└── ...
```

`onedrive_adapter.py`がOneDrive操作の抽象化を担当する。

## 6.3 OneDrive Adapter

外部へ公開する基本操作：

```python
folder_exists(folder_name)
ensure_folder(folder_name)
file_exists(relative_path)
download_file(relative_path, local_dest_path)
upload_file(local_source_path, relative_path, overwrite=True)
list_files(folder_name)
get_last_modified(relative_path)
```

呼び出し側は、OneDriveのHTTP仕様や共有URL形式を直接意識しない。

## 6.4 冪等性

月次フォルダ・月次ファイル生成は、

```text
存在する
  ↓
既存のものを利用

存在しない
  ↓
作成
```

とする。

`overwrite=False`の場合、既存ファイルがあれば処理を終了し、既存ファイルを利用する。

```text

```

## 6.7 Excel書き込み方針

既存のExcel書式を保持するため、対象セルの値のみ更新する。

```python

```

行・列の追加削除や、既存スタイルの再構築は行わない。

## 6.8 時刻

フロントでは時・分を別々に入力する。

```text
9時30分
 ↓
(9, 30)
 ↓
"9:30"
```

Excelへは先頭ゼロなしの`H:MM`形式で保存する。

# 7. バリデーション設計

## 7.1 基本方針

入力時と保存時の二重チェックとする。

```text
画面入力時
 ↓
行単位チェック

保存時
 ↓
月全体チェック
 ↓
保存直前に再チェック
```

## 7.2 主なルール

### VAL-01

日付が存在しない行には休暇種類を入力できない。

### VAL-02

日付が存在しない行には始業・終業時間を入力できない。

### VAL-03

以下の休暇区分では始業・終業時間を入力できない。

```text
有休
長期連休
特別休暇
欠勤
振替休暇
```

### VAL-04

土日かつ休暇種類が未選択で、始業・終業時間が入力されている場合はエラー。

### VAL-05

土日でも休暇種類が選択されている場合は、VAL-04のエラー対象外とする。

例：

```text
土曜日 + 休日出勤
```

などは入力可能。

## 7.3 UIによる予防

以下の場合、始業・終業入力をdisabledにする。

- 特定の休暇区分
- 土日かつ休暇種類未選択

ただし、入力済みの時刻がある状態で休暇区分へ変更した場合は、変更を禁止するのではなくエラーとして検出する。

## 7.4 時刻形式

```regex
^([0-9]|1[0-9]|2[0-3]):[0-5][0-9]$
```

例：


# 8. 排他制御・ロック設計

## 8.1 基本方針

一般ユーザーとadminの編集可能状態を逆にする。

```text
              未ロック       ロック中
一般ユーザー     ○             ×
admin            ×             ○
```

これにより、同一ファイルを一般ユーザーとadminが同時編集する可能性を構造的に下げる。

## 8.2 保存直前チェック

### 一般ユーザー

```text
保存
 ↓
バリデーション
 ↓
ロック状態再取得
 ↓
未ロック？
 ├─ Yes → 保存
 └─ No  → 保存中止
```

### admin

```text
保存
 ↓
バリデーション
 ↓
ロック状態再取得
 ↓
ロック中？
 ├─ Yes → 保存
 └─ No  → 保存中止
```

## 8.3 ロック管理

### 一括ロック

対象月の全ユーザーをロックする。

### 個別ロック

対象ユーザーのみロックする。

### 個別解除

対象ユーザーのみ解除する。

### 一括解除

機能として設けない。

## 8.4 OneDriveファイルの楽観的排他

`onedrive_adapter.py`には`get_last_modified()`を設け、将来的な楽観的排他制御に利用できる構造とする。

想定：

```text
ファイル読み込み
 ↓
更新日時/ETagを保持
 ↓
保存直前に再取得
 ↓
一致？
 ├─ Yes → 保存
 └─ No  → 他ユーザー更新として保存中止
```

ただし、現時点の疑似OneDrive実装では本機能は未完成である。

# 18. 設計上の重要ポイントまとめ

本システムの設計上、特に重要な点は以下である。

1. **Streamlit一体型アプリ**として構築する。
2. 画面・業務ロジック・外部連携を分離する。
3. ユーザー・ロック・設定はSQLiteで管理する。
4. 勤怠データ本体はExcelファイルで管理する。
5. 一般ユーザーとadminの編集可能状態をロックによって分離する。
6. 保存直前にも権限・ロック・バリデーションを再確認する。
7. OneDrive連携はAdapterに閉じ込める。
8. 現在は疑似OneDriveで開発し、本番OneDriveへ差し替え可能な構造とする。
9. Excelは既存書式を維持し、対象セルの値のみ更新する。
10. パスワードはbcryptでハッシュ化する。
11. PDFは現在の実装ではLibreOfficeを利用する。
12. DockerでPython・ライブラリ・LibreOffice・日本語フォントを含めた実行環境を統一する。
13. ページファイル名は英語で統一する。
14. 未検証のOneDrive本番連携と楽観的排他制御は、今後の技術検証事項とする。
